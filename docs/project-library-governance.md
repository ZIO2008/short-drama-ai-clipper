# 项目库治理

项目（剧目）的身份是 UUID；名称是面向操作者的唯一标识。创建或改名时会以 trim + 不区分大小写的名称检测重复，数据库触发器也会拒绝绕过 UI 的同名写入。历史重复名称不会被自动改名或删除；设置页会提示完整性风险，操作员先导出诊断包再处理。

## 归属和删除边界

| 数据 | 归属约束 | 删除边界 |
|---|---|---|
| 剧集、剧本、字幕、任务 | 必须属于一个剧目 | 删除剧目仅在用户确认后级联删除应用记录；不删除原片、剧本、字幕或导出文件 |
| 成果 | `generated_materials.drama_id` 必须等于任务的 `drama_id` | 删除剧集时保留已生成成果和任务记录，任务标为部分完成；不自动删除成果 |
| 剧本/证据 | 关联剧集必须属于同一剧目 | 删除剧集后外键置空，并重算剧本为未关联/待确认；失去剧集的 AI 证据不再参与范围推荐 |
| P1 草稿/时间线 | 草稿证据与任务必须同剧目 | 数据库触发器拒绝跨剧目引用 |

## 数据库防线与排查

迁移 13 增加同名剧目、成果—任务、剧本—剧集、证据—剧集、草稿—证据的跨项目写入触发器。启动健康信息还会以只读方式统计：外键违规、历史同名项目、已有跨项目引用。它不自动修数据、不删除文件。

异常处置顺序：先用“设置 / 数据与日志”导出诊断包和 SQLite 备份，再确认要保留的项目身份；通过应用内重命名、重新关联资产或人工迁移来修复。任何批量删除、合并剧目或清理历史包都需要单独列出精确对象并获得授权。

## 冻结能力的边界

P2 解说/TTS/旁白没有生产路由、preload API 或主进程 IPC，因此不参与本轮项目库运行路径。其遗留持久化代码引用的旁白表尚未纳入当前 schema；在 P2 被正式解冻前，必须先单独设计迁移、失败回滚和端到端测试，不能绕过冻结状态直接接入口。
