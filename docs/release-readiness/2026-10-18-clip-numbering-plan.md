# 统一切片编号执行卡

用户截图显示报告C-dfa49083/C-ed92f1e8与文件第02集_切片.mp4/第02集_切片_02.mp4没有共同标识。根因是UUID短码和文件碰撞序号职责混用，不是缺少一个显示后缀。

规划与完成标准：
1. 独立编号表保存候选UUID→分集内正整数，唯一约束防重号，按已有真实可见候选 created_at/id 顺序补号。新候选首次可见后续号；暂存且未发布项不占号；删除候选保留预留，不重排其他项。新增表不改证据快照或planned_range。迁移/重复启动/删除/回退旧程序后新增候选的补号均验证。
2. 候选合同增加可选编号，主键与选择事件仍用UUID。旧测试/历史缺号保留诚实回退，不编造编号。候选工作区、四项切换、池和报告复用既有文字数据槽，不改变DOM/CSS、窗口、导航或原型。按static-prototype-migrator分类为业务数据映射；影响文本另做双视口真实截图，不启动整页视觉迁移。
3. 新中文默认内部规则加入sequence，文件首次明确切片01；普通中文前缀保持。旧模板不改写，新含sequence规则重复碰撞使用再次导出02，通用uniqueOutputPath默认行为不影响其它产品。批次冻结编号，删除后报告仍能回链；历史文件保留原名/实际路径。
4. 完整单测、类型构建、独立两阶段审查、真实两候选导出及同候选重导、实际安装包验证。只读正式库一致快照上做编号迁移验证，核对候选/成果/字幕数量及原库哈希不变；正式启用由新程序正常追加迁移，前置完整备份，旧安装保留。

确定性：编号按分集永久递增，不等于当前筛选/批次数量；已经删掉或归档的号码不复用。旧文件本轮不自动改名，防止外部引用失效。范围仅原剧候选标识与命名，不改变生成算法、切点、字幕或源媒体。

修复边界：首次升级可确定性补号，旧程序新增但尚无号码的候选可继续补号；若数据库已记录编号迁移却整个编号表丢失，应明确停止并要求完整备份恢复，不能“修复”成重新从01编号而复用旧身份。
