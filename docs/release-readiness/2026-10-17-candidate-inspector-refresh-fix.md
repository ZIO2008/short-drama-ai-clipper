# 候选确认区生成期间闪烁：定位与修复计划

用户确认 0.1.101 已重试导出成功，随后三次正常使用的生成流程通过；新反馈仅为生成期间右侧候选确认区两种状态来回切换。三次正常使用观察可以登记通过，新增显示问题单独处理。

沿用 V49 完整快照及已验收工作区迁移卡 `docs/prototype-migration-card-original-clip-v49-runtime.md`。本轮只调整异步状态更新，不改 DOM 结构、布局、CSS、静态快照或交互入口；按 static-prototype-migrator 分类为纯业务状态修复，进入 bug-fixer。若定位发现需要结构变动，先重新评估本分类。

步骤与完成标准：
1. 用延迟响应、任务轮询和已存在/空候选分别复现确认区回退；核实原型脚本与真实状态是否争写，不能只凭截图认定根因。
2. 只修复证据支持的状态更新点；首次加载与真实读取错误仍明确显示，生成完成才展示真实新候选，失败不抹去稳定候选。
3. 延迟及乱序回归、受影响 Electron 流程、类型与构建、独立审查通过后按既有发布证据流程打包安装。生成算法、字幕资格、确认切点与导出校验均不变。

初始代码发现：桥接 `refresh()` 每次把已加载的候选置为 loading，`render()` 随即把已有候选切成“暂无可编辑候选”，响应后又恢复；需通过受控延迟验证该路径与用户闪烁现象的对应关系。生成轮询每 350ms 重绘，同样检查状态与节点是否发生无意义替换。

定向单测已复现已有候选在后台读取期间变成加载空态，修复后保持稳定；补齐空态/读取失败、已有候选失败禁确认及恢复、生成期间轮询与刷新、生成终态与延迟旧响应交错。终态发布使此前刷新请求失效，防止旧列表再次覆盖新候选。首次加载和真实错误继续显示；未重构生成轮询或改动任务预算。

真实 Electron 工作区五次刷新/十个采样保留同一候选，确认/音视频导出/报告闭环通过。包级测试另用本地受控 HTTP 延迟响应，在真实按钮启动生成期间连续采样候选确认区，并验证失败后已有候选保留；不调用付费模型或写入正式用户库。
