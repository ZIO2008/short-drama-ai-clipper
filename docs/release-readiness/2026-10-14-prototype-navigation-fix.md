# 切片工作区全局导航定点修复卡

用户现象：生成候选因字幕问题失败后，点击剧目库或任务中心出现“破茧之后、春江未眠”等演示剧目和任务。

证据：V49 完整 HTML 内嵌演示剧目库、任务中心和 `[data-screen]` 导航；其原型脚本直接调用 `showScreen`。`StaticPrototypeSurface` 的 clip 分支保留完整外壳，只初始化目标 screen 的 active 状态；运行时导航监听只处理 `[data-open], [data-r5-open]`，未拦截侧栏 `[data-screen]`。因此侧栏会在 iframe 内切到原型数据，与旧 v8.38.1 程序切换无关，生成失败不是必要条件。

分类：恢复既有全局导航的纯业务事件路由修复。沿用 current 指针注册的 V49 完整快照与 screen-clip 既有视觉基线，不修改 HTML/CSS、结构、尺寸、页面设计、数据库或候选生成条件。静态夹具继续保留原型演示行为；实际运行模式必须把四个全局导航目标交给应用外壳，并阻止原型监听器再次切屏。允许替换点仅为既有按钮回调，原型全局页面不接生产数据、不扩展本轮迁移范围。

执行：1. 添加可复现的侧栏事件回归测试；2. 连接受白名单校验的宿主导航事件，阻断原型事件继续执行；3. 复验真实剧目库/任务中心返回路径和静态夹具不受影响；4. 类型检查、构建、相关 Electron 测试及独立审查；5. 按当前候选治理生成独立修复包，验证实际包后再更新本机固定安装与入口，保留旧版本恢复锚点。

字幕失败另行取证，不根据截图中演示任务的“字幕识别失败”推断真实失败原因。只读数据中未找到与此次操作对应的新失败任务；需从实际错误提示、预检结果或日志确认，不能擅自降低字幕资格要求。

2026-10-15 补充取证：用户提供的实际提示为 ASR 时间锚点分布或覆盖不足，且没有质量合格字幕端点/PTS 已验证场景锚点。只读核对当前库 85 条 active ASR 轨道，仅第 1 集命中 sparse 条件：时长 280.08 秒、65 条 cue（最低数量为 15）、覆盖率 0.533、最大无锚点间隔 34.96 秒（当前阈值 20 秒）。此处因时间分布不足被预检阻断，不等同于 ASR 调用失败；不自动重跑收费识别或改写原字幕。

实际 0.1.95 安装包回归已复现：无字幕的隔离短视频生成预检失败后点击侧栏 library，iframe 仍为 1 个，期望为 0；这是确定的导航缺陷。第一轮测试曾因未预建临时 userData 目录而启动超时，修正测试准备后才取得上述有效复现，不把启动超时作为产品根因。
