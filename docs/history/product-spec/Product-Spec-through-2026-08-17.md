## 1. 产品上下文

### 1.1 产品摘要

这是 Windows 本地短剧素材管理与生产工具。本轮修复让操作者可将同一剧目的完整视频目录增量导入、按集号正确管理并在长列表中安全维护资产。

### 1.2 用户问题

用户每次导入都要重新定位同一目录；已有部分剧集时整批导入被阻断；列表按错误顺序显示且没有删除入口，85 集长列表无法继续浏览。

### 1.3 目标用户

| 用户类型 | 描述 | 核心需求 |
|---|---|---|
| 短剧投流素材操作者 | 在本地管理几十集到上百集原片 | 快速补齐剧集、确认顺序、修正错误引用且不伤害原片 |

### 1.4 成功标准

| 判断标准 | 目标 / 信号 |
|---|---|
| 批量补齐 | 已有部分剧集后再次选择完整目录，缺失剧集继续导入且已有项不阻断 |
| 正确顺序 | 1、2、3…10、11…顺序在资产页、数据库读取和生产选择中一致 |
| 长列表可用 | 85 集在 100%/125%/150% DPI 下可滚动至最后一行 |

## 4. 用户流程

### FLOW-001: 增量导入完整目录

**关联任务：** TASK-001
**入口：** 剧目资产页“导入视频文件夹”或编辑剧目“选择视频文件夹”。

**主路径：**
1. 系统以当前剧目最近成功导入目录作为系统选择器初始目录。
2. 用户选择一个视频文件夹；系统递归读取 mp4、mov、mkv、avi、webm。
3. 系统按集号自然排序并将候选与当前剧目比对。
4. 相同已有引用计入“跳过”；不存在的剧集导入；同集号不同文件计入“冲突”且保留已有引用。
5. 系统显示“导入 / 跳过 / 冲突”数量和可识别的冲突项，并刷新资产、健康概览和生产选择。

**边界情况：**
- 取消选择不改变最近目录或剧目。
- 文件夹没有支持视频时显示错误，不更新最近目录。
- 已有剧集不阻断其他缺失剧集导入。

### FLOW-002: 删除错误剧集引用

**关联任务：** TASK-002
**入口：** 剧目资产表每一行的“删除剧集”。

**主路径：**
1. 用户点击删除，确认框明确说明“只删除本软件引用，不删除原始视频文件”。
2. 用户确认后系统删除该剧集应用记录及关联的本地数据。
3. 系统重新读取资产、健康概览和生产资格，列表保持自然排序。

## 5. 功能需求

### REQ-001: 最近导入目录记忆

**优先级：** P0
**关联任务：** TASK-001

**规则：**
- MUST 按剧目保存最近一次成功导入的目录；选择单文件时保存其父目录，选择文件夹时保存该文件夹。
- MUST 在应用重启后仍可恢复，并仅在至少有一个有效导入结果时更新。
- MUST 对首次导入保留系统默认行为。
- MUST 保持文件选择与文件夹选择为两个独立 Windows 对话框。

**验收标准：**
- [x] AC-001: Given 某剧目已成功从目录 A 导入, when 再次选择文件或文件夹, then 系统对话框初始位置为 A。
- [x] AC-002: Given 应用重启, when 打开同一剧目的选择器, then 仍以 A 为初始位置。

### REQ-002: 自然排序与增量合并

**优先级：** P0
**关联任务：** TASK-001、TASK-002

**规则：**
- MUST 在写入、读取、资产页和生产输入中按数值集号升序排序；无集号项置于末尾并稳定排序。
- MUST 将同一真实路径或同集号同文件名的已有项作为跳过，不得使整批失败。
- MUST 将同集号但不同文件作为冲突，默认保留已有项并继续导入无冲突的其他项。
- MUST 返回并展示本次导入的 imported、skipped、conflicts 结果。

**验收标准：**
- [x] AC-003: Given 已有第 1 至 23 集, when 导入含 1 至 30 集的目录, then 第 24 至 30 集被导入，已有项被跳过。
- [x] AC-004: Given 文件名包含 1、2、10、11, when 读取或生产选择, then 顺序为 1、2、10、11。
- [x] AC-005: Given 同集号不同文件, when 导入, then 原引用不变、该项显示为冲突且其他无冲突项继续导入。

### REQ-003: 删除剧集引用

**优先级：** P0
**关联任务：** TASK-002

**规则：**
- MUST 在资产表每行提供删除入口及确认对话框。
- MUST 删除数据库中的剧集引用和应用拥有的关联记录，不得删除或移动 source_path 指向的文件。
- MUST 在成功或失败后给出明确反馈并刷新资产信息。

**验收标准：**
- [x] AC-006: Given 已导入剧集, when 确认删除, then 列表和计数减少且原文件仍存在。

### REQ-004: 长列表浏览

**优先级：** P0
**关联任务：** TASK-003

**规则：**
- MUST 让剧目资产页和表格所在主内容区拥有可达的垂直滚动路径。
- MUST 支持鼠标滚轮、滚动条、PageDown、End 到达最后一集。
- MUST 在 100%、125%、150% DPI 下不因固定高度或 overflow 裁切资产行。

**验收标准：**
- [x] AC-007: Given 85 集剧目, when 使用 End 或滚动条, then 最后一集可见且操作列可用。

## 10. P1 供应商选择与配置引导（v0.1.17）

### 10.1 问题与目标

现有“能力供应商”入口要求用户先知道供应商名、地址、模型和计费方式，实质是在把产品的选型工作丢回给用户。P1 必须把它改为可筛选的本地供应商目录：用户先按自己要做的能力、费用偏好、质量取向和接入难度选择，再只补该方案确实必要的配置。

本轮只覆盖已被产品使用或已向用户展示的三项能力：`asr`（字幕识别）、`text-analysis`（剧情语义分析）、`multimodal-review`（关键帧/候选片段复核）。P2 解说/TTS/旁白继续冻结，目录、路由、preload 和 IPC 均不得让它变成可用能力。

### 10.2 供应商目录规则

| 编号 | 规则 |
|---|---|
| SUP-001 | MUST 将供应商资料定义在可独立维护的目录数据中，不得散落在 React 组件中。资料至少含：支持能力、区域、费用类型、质量定位、适用/不适用场景、接入难度、预填 endpoint/model、是否需要密钥、官方文档与价格页、核验日期。 |
| SUP-002 | MUST 允许按能力、费用类型（本机运行/免费额度/按量付费/试用待确认）、质量定位和接入难度筛选；无匹配结果时解释如何放宽条件或使用自定义接入。 |
| SUP-003 | MUST 明确“免费额度”不等于永久免费，“本机运行”不等于零成本；所有目录项显示对应提醒，不显示未经官方确认的具体免费额度。 |
| SUP-004 | MUST 将选定项预填到现有配置草稿，保留用户尚未保存的自定义字段；选择目录项不保存、不上传、不覆盖现有密钥，只有用户确认保存才更新该能力的本机默认方案。 |
| SUP-005 | MUST 保留“自定义接入”入口，允许用户填写非目录供应商；已保存的旧配置可继续读取、编辑和保存。历史 `text_semantics`、`video_understanding` 配置必须映射为 `text-analysis`、`multimodal-review`，不得丢失密钥引用。 |
| SUP-006 | MUST 让目录选择实际影响能力状态和项目推荐：已保存本机方案或已保存有效密钥的云端方案显示“已配置”；无方案、缺密钥、能力不匹配显示具体处置。当前 P1 仍仅运行受控本地实现，已配置不表示真实云端调用已启用。 |
| SUP-006a | MUST 将目录中“请按…填写”一类模型引导文案视为未配置草稿，而非模型 ID；Renderer 保存前与主进程持久化层都必须拒绝该值。拒绝不得新建、替换或删除密钥引用。 |
| SUP-006b | MUST 对产品维护的目录方案由产品负责模型选型，普通用户只需注册供应商账号、创建并填写 API 密钥。保存或测试密钥后，主进程仅向官方受限模型目录请求可用模型，按产品维护的“能力兼容性 + 优先级”自动选择并保存一个模型；不得要求普通用户检索、猜测或手填模型 ID。模型目录、优先级和兼容性规则必须在共享目录数据中维护，不能散落在页面中。 |

| SUP-006d | MUST 仅把“目录中已列为视频理解兼容”的已开通模型自动选为 `multimodal-review` 默认模型。若账号没有兼容模型，明确显示“账号未开通视频理解模型”，提供当前目录项的官方开通/模型页，并保持能力为受控状态；不得将“模型列表连通”伪称为视频理解可用。仅“自定义接入（高级）”可手动覆盖模型，且须保留安全/兼容性风险说明。 |

### 10.4 用户流程

1. 用户进入“设置 → 能力供应商”，先选择要解决的能力，再按费用、质量和接入难度筛选候选。
2. 用户展开候选，阅读适合什么、不适合什么、费用提醒、数据区域提醒及官方文档。
3. 用户选择“使用此方案”后，系统仅预填供应商、区域、endpoint、超时与价格提示；目录方案的模型由产品自动发现、选择并显示。对需要密钥的云端方案，普通用户只填写 API 密钥；对本机方案提示检查本地服务地址。

### 10.5 安全、隐私与验收

- 密钥只经现有 Windows 当前账户级安全存储保存；目录不得携带密钥、示例密钥或跟踪请求。
- SUP-011：供应商认证字段 MUST 由独立的认证 schema 声明，而非按供应商在页面、保存逻辑或安全存储中硬编码。schema 可声明 1 个至多个敏感字段；保存时将同一供应商的全部字段作为一个带版本、schema 标识和字段对象的加密凭据包写入单一 `secret_ref`。新代码必须读取该包；既有裸 API Key 与历史腾讯云 `{ SecretId, SecretKey }` 记录继续只读兼容，直到用户主动重新保存。不得为腾讯云或任一供应商新增专用凭据表、专用存储分支或要求更新后重填未变凭据。

- AC-SUP-002：选择目录项会预填配置但不覆盖已保存密钥；用户保存后对应 `asr`、`text-analysis` 或 `multimodal-review` 的能力状态正确刷新。
- AC-SUP-003：旧 `text_semantics`、`video_understanding` 配置迁移后仍可读取，原 secret_ref 保留。
- AC-SUP-004：无密钥云端方案显示“缺少密钥”；本机方案显示“需确认本机服务”，当前 P1 项目页始终说明“受控本地实现，云端适配器未启用”。

| CLIP-009 | 时间轴优先与智能排序隔离 | 自动候选的入点与出点必须落在通过质量门禁的**切点锚**上，不能由模型凭空给出秒数、固定步长或猜补时间码。对白/画面文字候选只使用导入、OCR、ASR 的合格语义事件外侧边界；没有合格字幕的动作、情绪、视觉揭示或叙事环境事件，可使用源视频中已验证的镜头/场景转场锚点。此类锚点必须保存验证时的源媒体指纹、PTS 验证和规则版本，并在生成前与当前分集媒体指纹重新比对；重关联或源文件变更后旧锚点自动失效，未经重新验证不得使用。剧情、画面、音频分析负责识别事件、选择锚点组合、排序并保留依据，不能任意移动锚点、绕过门禁或替代确认；分析未启用、失败或低置信度时，不得伪造候选。人工只审核已自动生成候选的结论，并仅在输出边界本身不清晰时少量帧微调；人工新建候选不得成为自动能力缺失、来源冲突或缺锚点的兜底。确认仍是进入导出的唯一授权。 |
| CLIP-010 | 多源字幕时间轴与逐段自动裁决 | OCR 与 ASR 是独立证据轨；“导入”仅为获取途径，不能单独定义证据性质。系统不设按来源自动选定的“默认切点轨”，也不得按全剧硬优先级覆盖另一来源：OCR 忠于画面文字，ASR 忠于实际声音；导入文件必须依 CLIP-015 的已核验性质参与裁决。自动候选按每个候选边界及相邻时间窗读取合格的各轨证据，并自行作出可追溯裁决：仅 ASR 的对白时段以 ASR 保护音频首尾；仅 OCR 或已核验为画面对齐的导入字幕的画面文字时段以该轨保护画面文字首尾；OCR 与 ASR 文本一致但时间码不同，切点优先采用 OCR 的画面时间，ASR 继续保留为声音证据。敏感词替换等同一时间窗内的文本差异只标为内容差异，不单独阻断边界生成；只有时间窗对候选边界给出不相容约束时才标为时间冲突。文本不同、时间不重叠或任一侧缺失时必须保留来源与原始时间，标为差异/缺失侧，不得自动改字、整体平移或合并成伪“统一字幕”。没有已定义自动裁决规则的时间冲突不得转交人工决定：系统必须排除该边界并寻找其它合格边界；没有任何合格边界证据时阻断自动生成并说明原因。人工审片只审核已自动生成候选的结论；仅在输出边界本身不清晰时允许前后少量帧微调，不能作为来源冲突、缺时间轴或缺候选能力的补丁。确认仍是进入导出的唯一授权。 |
| CLIP-011 | OCR/ASR 同一语义事件对齐 | 多源对齐的单位是同一语义事件，不是单条 cue 或字符串全等。系统必须允许相邻 OCR cue 与一个连续 ASR cue、或相邻 ASR cue 与一个 OCR cue 的 `n:m` 对齐；判断至少综合时间重叠/相邻间隔、去除标点和空白后的文本相似度、相邻 cue 的可合并连续性。OCR 的编辑性断句、换行、标点差异及 ASR 的连续输出不得单独构成内容或时间冲突，例如“我有一个苹果，很好吃。你试试看。”与“我有一个苹果很好吃你试试看。”应可对齐为同一语义事件。各来源原始 cue、文本与起止时间必须保持不变；事件对齐只产生可追溯关联和裁决依据，不能重写任一来源的时间码或文本。 |
| CLIP-012 | 语义声音、镜头与叙事环境锚点 | 原始波形有能量不等于必须保留：普通气口、呼吸和中性环境底噪可在合格 OCR 字幕出现处断开，不得因 ASR 或波形略早就全局覆盖 OCR 的视觉边界。对白候选中，合格 OCR 是默认视觉起点；ASR 仅在 OCR 缺失或有可追溯语义证据表明 OCR 之后仍漏掉关键台词时参与冲突裁决。候选内部发生的源片镜头切换是原始编辑事实，不得反向移动或切碎该对白事件。尖叫、哭声、笑声、打斗喊声等表演性非语言声音，以及打雷、雨声骤起、警报等与后续关键戏同一连续场景、明确建立氛围/预示/衔接关系的叙事环境声，可作为非语言事件参与自动选段；其候选起止仍须落在最近合格的镜头/场景结构锚点，禁止固定提前/延后补偿或因持续环境声跨越无关段落无限扩张。 |
| CLIP-013 | 候选叙事节拍完整性 | 候选的完整性由已成立的叙事节拍决定，不等于必须演完一整场戏或固定时长。允许在爆点、悬念、反转或关键反应刚出现时结束（`peak_or_turn`），也允许在冲突、动作或反应完成后结束（`resolution_or_afterglow`）；两者都必须有可追溯事件依据并落在合格切点锚上。禁止在情绪/动作/信息仍处于上升中段，或已过高点却刚开始回落、尚未形成新节拍或结论时结束；无法判断结束是否属于允许节拍时，不自动生成该候选。排序必须记录候选的结束类型与依据，确认仍由操作者完成。 |
| CLIP-014 | 候选上下文可用性 | 原剧切片候选只须满足自身叙事节拍完整性，不强制在脱离原剧后仍能自解释。系统必须为每个候选给出可追溯的上下文可用性标记：`standalone_ready` 表示仅凭候选本身可基本理解其触发、关系或结果；`context_needed` 表示候选作为情绪、爆点、反应或局部动作素材成立，但依赖前后剧情、其它候选或后续解说才能完整理解。该标记仅影响候选排序、筛选和后续智能剪辑/解说的编排依据；不得因此自动复制生成两个版本、补造上下文、改变已通过的切点锚，或把 `context_needed` 排除出原剧切片候选池。 |
| CLIP-015 | 导入字幕获取途径与证据性质分离 | 每条字幕资产必须分别保存 `acquisition`（`imported` / `system_asr` / `system_ocr`）、`evidence_nature`（`audio_aligned` / `visual_aligned` / `reference_unknown`）和独立的时间质量门禁结果。普通文件导入默认 `imported + reference_unknown`，不要求操作者在导入时猜测其来源，也不能单独作为自动切点锚。系统仅在同一剧集、同一语义事件中与合格 OCR 或 ASR 的文本及时间行为存在明确、可追溯且无冲突的互证时，才可将导入字幕标记为对应的 `visual_aligned` 或 `audio_aligned`；同时符合两侧、证据不足或存在冲突时维持 `reference_unknown`。剪映等外部识别工具导出的字幕不因文件名、导入入口或文字内容被推定为声音对齐；所谓源字幕也不因“源”字被推定为画面对齐。`reference_unknown` 可保留、查看和参与文本参考，但不得单独驱动自动候选边界；它不改变 OCR、ASR 或原始导入文件的 cue、文本和时间码。 |
| CLIP-016 | 候选起点资格与上下文解耦 | 候选没有固定的最小铺垫、前情或时长要求。它可以从已成立的铺垫/触发（`context_setup`）、事件进入（`event_entry`）、情绪/冲突/信息的高点或反转本身（`peak_entry`），以及完成后仍有意义的反应/余波（`aftermath_entry`）开始；高点本身是合格起点，不得因缺少前情被过滤。起点仍必须落在 CLIP-009 的合格锚点上，不得切断关键台词、表演性非语言声音或动作/信息事件的不可分中段。系统必须记录起点类型及其事件依据；候选是否脱离原剧后可理解，仅由 CLIP-014 的上下文可用性标记表达，不得反向收窄可选起点或制造补前情的重复版本。 |
| CLIP-017 | 候选叙事去重与用途变体 | 候选生成必须默认压制同一叙事节拍的机械重复：锚点组合相同，或起止虽有极小差异却不改变已覆盖事件、起止节拍、上下文可用性或剪辑用途的候选，只保留排序更高且依据更完整的一条。不得用固定重合百分比、候选编号或模型给出的不同标题伪造差异。范围不同或剪辑用途确有不同的候选可共存，例如一条是完整冲突场景，另一条是同场的高点爆发；共存时必须分别记录 `editorial_purpose`、所覆盖事件、起止类型和保留理由，使其可被后续智能剪辑区分使用。去重不应因候选来自同一源片、共享部分时长或需要上下文而压掉有效变体；若无法确认是否存在实质区别，则不自动保留低排序的重复候选。 |
| CLIP-018 | 候选时长偏好与节拍优先 | 用户配置的时长范围是候选排序偏好，不是可打断有效叙事节拍的硬截断线。系统应优先在范围内寻找同时满足起点、结尾、声音/画面完整性和去重规则的候选；为保留合格起止节拍而略短或略长时，候选仍可生成，但必须记录期望范围、实际时长、偏离方向和具体保留理由，并在同等质量候选中降序。不得静默放宽时长，也不得因为满足范围而在上升中段、台词/动作不可分中段硬切。时长偏好不授权候选无限扩张：若延伸后没有新的合格节拍、不能说明保留理由或只能产生低价值重复，应停止扩展、降级排序或不生成。 |
| CLIP-019 | 候选证据快照与重算隔离 | 每个生成候选必须固化本轮使用的源视频身份、字幕资产及其版本、语义事件关联、锚点、质量门禁结果、排序/去重/时长规则版本与生成配置快照；审片、确认和导出始终读取该快照，不能因 OCR/ASR 重新识别、导入轨更新、规则升级或当前轨切换而静默移动边界、改变解释、重排或撤销已存在候选。新的合格字幕/规则可将旧候选标为“存在可重算证据”，但只允许由明确的新一轮生成创建独立候选集合；旧集合、其确认状态和已导出成果必须保留可追溯关系。重算不得覆盖、删除或复用旧候选 ID；无论新一轮成功、失败或被取消，旧候选均维持原状态。 |
| CLIP-020 | 单集边界与轻量邻集剧情上下文 | 原剧切片的每个候选必须完全落在当前选中剧集的源视频时间轴内，不得跨集拼接、借用前后集画面或把邻集锚点当作本集切点。为判断人物关系、反转、悬念、回收和上下文可用性，分析可只读使用当前集完整证据以及相邻剧集的已存摘要、剧本或字幕文本等轻量剧情上下文；不得因理解上下文而重新扫描、转码或多模态分析邻集完整视频。上下文输入必须随候选快照记录其剧集、资产版本和可用状态；缺失、质量不足或相互矛盾时，系统只以当前集证据生成或不生成候选，并标注 `context_limited`，不得编造前情、把推断当事实或阻断本集已有充分依据的候选。 |
| CLIP-021 | 源片精确定位与转码导出分离 | 源片时间定位与导出编码是两项独立职责：候选入/出点及微调必须依据 FFprobe/解码可验证的源片 PTS 时间戳和相邻可呈现帧，不能用假定的 25/30fps 帧号代替；源片为可变帧率不是阻断候选或正式导出的理由。确认后的正式导出必须从已固化的精确边界解码并按用户选择的编码、码率/目标体积、尺寸、封装和字幕策略重新编码，从而同时保证切点精度与文件大小控制；不得改写原片。流复制只可作为界面明确标注为“快速预览、边界可能受关键帧限制”的可选路径，不能冒充正式精确导出。仅当源片 PTS 不可读、损坏、非单调或无法在预览/解码中复核边界时，才阻断相关自动候选或正式导出，并保留具体探测原因；不得因“可变帧率”本身阻断、强制转为固定帧率或覆盖源文件。 |
| CLIP-022 | 字幕资产前置与切片读取边界 | 字幕资产中心与原剧切片是独立工作流：ASR、OCR 和外部字幕导入只能由字幕资产中心的明确操作创建、更新或重试；进入切片或点击“生成候选”只读取当时已持久化的字幕轨、质量门禁和版本，绝不得隐式发起识别、导入、重试、覆盖当前轨或消耗字幕识别资源。切片预检必须如实展示可用/不可用的既有证据。没有合格字幕时，仍可依据 CLIP-009 的镜头/场景锚点生成动作、情绪、视觉揭示或叙事环境候选；但任何需要对白/画面文字边界的候选必须因缺少既有合格轨而排除，并提供“前往字幕资产处理”的入口。不得把切片缺字幕解释为后台正在识别，也不得以临时转写或猜测时间码绕过资产中心。 |
| CLIP-023 | 候选生成的分层复核与资源边界 | 候选生成采用两层：第一层仅读取 CLIP-022 已持久化的字幕资产及其版本、源片可验证的镜头/场景结构和轻量剧情上下文，完成事件关联、合格锚点组合、节拍完整性、时长偏好、去重与初始排序；不得在此层重新运行 ASR/OCR、导入字幕或对全片逐秒进行重型视频理解。第二层只对第一层高排序候选，或因画面/事件证据不确定而需要复核的少量候选，提取其必要时间窗进行视频多模态复核。复核必须保留触发原因、输入范围、结果与耗时；通过则补强或调整排序，失败、超时、不可用或仍不能证明边界/事件时按已定义规则降序或排除，不能生成虚假通过、扩大到整集重跑或转交人工兜底。两层的输入、版本、触发与结果均随 CLIP-019 候选快照固化。 |
| CLIP-024 | 候选审片的最小可操作证据 | 每条自动候选必须在现有候选检查器内提供紧凑、结构化且可定位的审片摘要：来源集与源时码、起点/结尾节拍类型、核心事件与 `editorial_purpose`、具体字幕语义事件或镜头/场景锚点、上下文可用性、时长偏离及理由、第二层复核状态，以及影响结论的 `context_limited`、重算可用等警示。摘要中的每项必须可回指 CLIP-019 快照中的原始证据；操作者只需据此审阅候选结论和必要的少量帧微调，不必进入字幕资产中心逐 cue 比对。不得显示模型思维链、无证据的泛化评分、原始提示词或冗长推理文本；不得为这些信息另开页面、改变已确认的工作台主结构，或把缺证据伪装成“AI 已理解”。 |
| CLIP-025 | 文本语义必需与视频复核可选 | 文本语义分析能力是自动候选生成的前置条件：它必须基于 CLIP-022 已持久化的字幕/剧本和 CLIP-020 的允许上下文，实际完成剧情事件、人物关系、冲突、反转/悬念、节拍及候选用途判断。未配置、不可调用、超时、失败或返回不能满足结构化输出质量门禁的文本语义能力，系统必须阻断自动候选生成并说明具体原因；不得用锚点规则、固定模板或无语义排序伪装为智能候选。视频多模态复核是 CLIP-023 第二层的可选增强：不可用、失败或未触发时，只要第一层已有充分、可追溯的文本/结构证据，候选仍可生成并如实标注未复核；但仅能由视频内容证明的重要性或边界，在缺少该证明时不得虚构视觉结论或保留为自动候选。两类能力的实际提供者、本地/云端状态、调用结果与版本都必须进入候选快照。 |
| CLIP-026 | 已配置文本语义供应商的非破坏继承 | 当前用户已保存的文本语义供应商配置是候选生成的可用输入，不得要求用户因开发、升级、打包、候选任务失败或设置页重构而重新填写。实现必须按能力标识读取既有 profile 和其受系统保护的密钥引用，兼容历史 `text_semantics` 到 `text-analysis` 的迁移；迁移必须幂等、可回滚，保留 endpoint、model、区域、超时、默认归属和密钥引用，不能用空草稿、硬编码默认值或新应用数据目录静默覆盖。候选生成预检、连接测试、模型调用失败和取消只可返回状态/原因，绝不得清空、替换、重置或明文回显已保存密钥；只有操作者在设置中明确保存、移除或替换时才可变更配置。开发开始前必须以只读方式验证当前配置记录和密钥引用可解析，但不得在日志、测试快照、诊断包或代码中读取/输出密钥明文。 |
| CLIP-027 | 语义分析分窗与接缝排除 | 分窗只解决文本语义模型的上下文预算，绝不是叙事事件、候选或切点边界。系统必须先保留完整的原子证据序列（字幕语义事件、镜头/场景锚点、时间码及允许的轻量上下文），再以可变长度的“核心证据单元 + 前后保护上下文”形成分析窗口；不得按固定字数、固定时长或模型上下文耗尽位置直接切断事件。每窗只输出可回指原子证据的事件地图，包括事件 ID、开始/持续/升级/反转/完成状态、人物/冲突、关联证据和接缝连续性；跨窗同一事件必须合并为同一 ID，摘要只帮助全局理解，不能单独决定候选或时间码。任何候选的起止均须回到原始字幕/镜头锚点与 PTS 复核，禁止落在人工窗口接缝。接缝连续性不清时，系统至多扩展到该接缝两侧各一个相邻完整证据单元后重新分析；仍无法闭合、无法合并事件或无法证明合格锚点时，必须排除候选，不得继续无限扩窗、猜接续或转给人工兜底。事件地图按所用字幕/剧本/上下文版本缓存；只改数量、时长或排序时复用缓存，证据版本变化才重建。 |
| CLIP-028 | 模型选锚与程序精确解析契约 | 文本语义模型和视频复核模型必须通过本轮快照中系统提供的事件 ID、字幕锚点 ID 或镜头/场景锚点 ID 表达候选选择；模型选择的起止 ID 即是其提出的切点，程序再从不可变锚点记录解析对应的精确 PTS 与相邻可呈现帧。模型不得输出、修改或覆盖任意秒数、帧号、PTS、cue 文本或锚点定义；这些字段出现、未知 ID、跨快照 ID、起止顺序错误、事件/节拍不相容或无对应证据时，程序必须拒绝该输出。调用应优先使用供应商支持的结构化 JSON/工具参数约束；无原生严格约束时仍必须进行应用侧 schema、ID 存在性、证据归属和边界质量校验。首次无效可进行一次仅含校验错误的结构化修复请求；修复仍无效、调用失败或超时即不生成候选，不得解析自由文本猜切点、回退为模型秒数或转给人工补足。模型选择、程序解析、校验结果和一次修复记录均写入 CLIP-019 快照。 |
| CLIP-029 | 本地剧集证据包、覆盖图与质量门禁 | 自动候选生成前，系统必须为当前集构建并持久化版本化的本地“剧集证据包”，而不是把整集交给模型后以摘要代替事实。证据包至少绑定源视频身份/文件指纹、真实 PTS 与可读性、不可变的 OCR/ASR/导入字幕原始轨道及其来源和质量状态、镜头/场景与音频结构锚点、允许的剧本/邻集上下文版本，并以字幕起止、镜头/场景变化、语音/静音结构等真实锚点划分原子证据单元；禁止按固定秒数生成伪证据格。OCR、ASR 与导入轨道只可建立可回指 ID 的 n:m 语义关系，绝不得改写、合并、覆盖原 cue 文本或时间码；能量/VAD 仅可补充语音/静音结构，不能单独证明语义、剧情价值或切点。系统必须为每个原子单元建立覆盖图，明确视觉字幕、音频文本、镜头/场景、视觉事件、环境连续性中的可用、冲突、缺失或不确定状态及来源版本。候选仅可依赖其关键起止、核心事件和完整性结论均有适配的合格证据覆盖的区间：对话/画面文字候选需要文本语义和相应的合格文本轨道，需画面干净字幕边界时以合格 OCR 为准；语音完整性候选需要合格 ASR/音频文本；无字幕动作、表演或环境叙事候选必须有源视频与镜头/场景连续证据，任何只能由具体视觉内容证明的结论仍受 CLIP-025 视频复核约束。关键区间缺失、冲突未闭合、PTS 不可复核或关键结论无来源时，只阻断依赖该区间的候选并说明准确缺口，不得阻断无关候选、静默降级、让模型猜测或转交人工补足。模型调用只可读取本地证据包中与任务相关的最小原始证据及事件关系；所有外发材料、提供者、版本和结果均须进入快照，源视频和全量证据包默认留在本地。验收必须证明每条候选的 PTS 锚点可解析、关键结论可回链、OCR/ASR 冲突不被静默合并、无证据候选被拒绝；开发验收可使用独立真实样本集评测，不得把运行时人工审片变成能力兜底。 |
| CLIP-030 | 四级证据资格与三级候选资格 | CLIP-029 覆盖图中的每一项证据及其关系必须带有可解释资格：`A 主证据`（来源、时间轴和对应关系均可复核）、`B 辅助证据`（可佐证但不能独立决定边界或剧情结论）、`C 冲突/未闭合`（存在但与其他轨道冲突或对应关系未证明）、`D 缺失/不可用`（不存在、损坏或不可复核）。资格必须记录判定理由、来源版本和作用范围；文本/视频模型的输出只是候选结论，不属于任何证据资格，不能把 B/C/D 升级为 A。有效 PTS 只可作为时间定位主证据而非剧情主证据；合格 OCR 可作为可见字幕锚点，合格 ASR 可作为声音文本锚点；导入轨道在被符合 CLIP-015/CLIP-029 的证据证实前不得自动升为 A；镜头检测只可证明结构变化，VAD/能量最高只能为 B；视频复核只可使其已验证的具体视觉事实成为 A。候选资格仅有 `qualified`（全部关键起止、核心事件和完整性结论各有适配 A 主证据）、`qualified_with_limit`（关键结论均为 A，但非关键区间存在 B/C，必须降序并在 CLIP-024 检查器明示限制）和 `blocked`（任何关键结论仅有 B、处于 C/D、PTS 不可解析或冲突未闭合）。`qualified_with_limit` 不是待人工补证据状态；`blocked` 必须直接拒绝生成并给出具体缺口，运行时人工审片仅可审核已合格候选的结论和少量帧微调，不得把候选升级为合格。 |
| CLIP-031 | 证据自动核验、声明范围与冲突分类 | 证据包构建必须依次运行媒体、轨道、视觉/音频时间、跨轨关系、覆盖图和候选依赖核验，并把每个判定的规则/校准配置版本与失败原因写入证据包。媒体核验确认文件身份、当前集归属、可解码性、单调 PTS 和锚点帧可解析；OCR 核验仅对已校准区域内可见文字的起止/稳定性作视觉声明；ASR 核验仅对真实音频中的语音文本及其时间范围作音频声明；导入轨道核验其来源性质与已验证的时间/语义行为；镜头核验只声明结构变化；VAD/能量只声明语音/静音结构；视频复核只声明可回指已核验片段/帧的具体视觉事实。不得以单一全剧置信度、固定通用毫秒阈值或模型自报置信度决定资格；需要数值的 OCR 稳定性、ASR 对齐、镜头检测等阈值必须按证据类型和素材特征使用版本化校准配置，并仅以独立真实样本集的开发验收更新，运行时不得由人工临时放宽。当前集/来源不符、PTS 越界或不可解析、同一被主张事实的文本/画面/声音直接矛盾、以及无法确定的 n:m 对应关系均须显式标为 C 或 D 并给出类型；OCR 的可见时间与 ASR 的起音时间不同、或 ASR 合句而 OCR 分句，本身不是冲突，必须保留各自声明范围并建立关系待核验。候选核验必须逐项列出其关键起止、核心事件和完整性结论所引用的 A 证据，任何引用缺失、越权声明、低资格替代或未闭合关系都应当阻断生成。 |
| CLIP-032 | 独立真实样本集与编辑接受范围验收 | 证据资格、校准配置和候选质量必须由版本化、只读的独立真实样本集验收，不能以旧版本候选、模型摘要或开发者主观观感作为正确答案。初始基线分三层：约 20–30 个可快速复现的真实短片段/轨道夹具用于硬门禁回归；约 6 集完整真实剧集作为公开开发集用于日常回归和校准；约 2–3 集未参与参数选择的完整真实剧集作为隐藏验收集，仅用于大版本候选验证。全部素材、原始轨道、证据包版本和场景卡必须冻结并以清单/指纹绑定；任何改动须新建基线版本、说明原因并保留历史结果，禁止静默替换或修改样本以掩盖回归。每张场景卡至少定义核心事件、合格/缺失证据、允许的起止锚点或完整候选组合、禁止区域、必要的视觉复核、允许限制及应生成或应阻断的结果；不得要求唯一秒数或固定候选数量。样本必须覆盖 OCR/ASR 一致与错位、分句差异、OCR 缺失、导入来源未知、无字幕动作/表演、台词中途切镜、环境叙事、高潮/反应/余韵、VFR/转场风险和证据不足阻断。验收硬指标为 PTS 可解析、关键结论 A 证据回链、冲突显式化、应阻断场景不生成、配置/历史快照不丢失，均须为 100%；编辑验收检查充分证据的关键事件至少有一个候选覆盖、候选不进入禁止区域且命中任一允许组合。证据包构建必须可重复；模型候选允许排序或有效变体不同，但每条都必须通过 CLIP-029 至 CLIP-031，不能因重复运行产生越权锚点、无证据候选或混用版本。样本基准中的人工只在开发验收阶段一次性标注可接受与不可接受边界，绝不进入用户运行时或承担模型失败兜底。 |
| CLIP-033 | 候选资格的就地反馈与恢复路径 | 候选工作区必须将“合格候选”“可用但受限候选”“证据阻断”和“任务失败”作为四种不同用户状态呈现，且只在既有候选生成反馈、候选卡、右侧检查器和任务中心/完成报告中补充真实数据，不得另建质量诊断页、把技术日志塞进主工作区或以泛用弹窗打断日常审片。`qualified` 按正常候选呈现；`qualified_with_limit` 仍可审阅、微调和确认，须在候选卡及 CLIP-024 检查器用一句具体、面向编辑的限制说明（如前情受限、未完成视频复核），同时明确核心事件和切点证据完整，降低排序但不得用笼统“低置信度”或颜色单独传达；`blocked` 不是失败候选，不进入候选卡或候选池，只在本次生成摘要/无候选状态说明“未纳入”的数量和具体关键缺口，明确系统未猜测切点。真实执行失败才以错误状态呈现：文本语义调用无可验证结果可提供“重新生成候选”，只重跑语义/复核而不触发 OCR、ASR、导入或覆盖旧候选；字幕证据缺失的唯一主操作为“前往字幕资产”；媒体/PTS 不可复核的唯一主操作为“查看素材资产”。每条就地说明必须用事实、影响和下一步三部分说明，例如“关键台词缺少可用时间证据。为避免切断对白，系统没有猜测切点。前往字幕资产”；不得显示 A/B/C/D、置信度、错误码、模型思维链、原始提示词或技术术语。局部反馈贴近当前集/候选，任务完成、失败和待处理原因同时进入可持久回看的任务中心；任何恢复操作不得删除证据包、重置供应商配置、改变旧候选或要求人工补足证据。 |
| CLIP-034 | 分层视频复核的触发、预算与稳定快照 | 视频多模态复核只能作为 CLIP-023 的第二层证明手段，绝不得扫描整集或因候选生成而重跑 OCR/ASR。第一层先以本地证据包、文本语义和结构锚点形成内部候选与证明缺口；只有无字幕动作/表演/反应等关键视觉事实、画面干净边界决定候选是否成立、或环境叙事的场景连续性无法由既有证据证明时，才标记为“必须复核”。文本与结构证据已闭合的普通对话、仅因排名高的候选、以及视频也无法解决的文本语义关系未闭合，均不得触发复核；后者直接按证据门禁阻断。每次调用只可取核心完整证据单元及其前后各一个相邻单元，或起止锚点前后的实际 PTS 帧序列，返回可回指片段/帧 ID 的“成立/不成立/看不清”具体视觉事实和可用锚点，不得输出秒数、自由叙述切点或替代文本证据。视觉复核属于可选增强而非关键证明时，可按版本化预算挑选少量“推荐复核”候选；预算只能限制推荐复核，不得将必须复核候选降为合格：必须复核者须完成复核或 `blocked`。本轮至多进行一次受控视觉重试；仍失败时，依赖视觉事实的候选 `blocked`，文本/结构已足以闭合的候选按 `qualified_with_limit` 输出。候选工作区只能在本轮所需复核完成、失败或按门禁收束后发布稳定候选快照，禁止先展示后在后台静默改写候选；进行中在既有任务反馈中显示正在复核的关键片段数、已耗时、可取消入口和剩余状态。取消仅停止未完成调用并保留旧轮次/配置；耗时、范围、提供者、版本、输入清单、重试、取消和结果必须写入 CLIP-019 快照及任务中心。 |
| CLIP-035 | 原剧切片数据生命周期与安全清理 | 原剧切片必须将源码仓库、应用数据、独立验证样本和发布候选物理隔离；源码仓库只存代码、文档、迁移和可复现测试夹具，禁止写入真实用户视频、用户数据库、关键帧缓存、临时切片、运行输出或密钥明文。每个落盘产物必须由本地清单记录产物 ID、类型、来源视频指纹、生成规则/配置/版本、大小、创建时间、引用者、是否可重建、清理资格和清理记录；不得按文件名、目录猜测或最后修改时间直接删除。源视频、原始导入文件、已确认候选、导出成果、原始字幕证据、仍被候选/导出/任务/样本引用的证据包和快照均为不可自动删除资产，只能经其已有明确删除流程处理；删除字幕资产不得删除源视频、ASR/OCR 或已确认/已导出历史，删除或重建只影响后续轮次。关键帧、局部复核片段、可重建事件/模型缓存只可在无任何引用、可按清单重建且未被运行任务占用时，按版本化容量预算和最久未用顺序清理；失败/取消任务的临时文件须在终态后完成引用核验才可清理并记录原因。所有新产物必须先在受控临时位置生成，校验文件/PTS/哈希与清单后原子提升为正式产物；失败、取消、升级和迁移不得覆盖上一次有效证据包或留下可被误引用的半成品。空间不足时先清理合格的可重建缓存；仍不足则阻止新缓存/任务并给出空间原因，绝不删除用户源文件、成果、候选或被引用证据。安装包、升级、开发测试和故障恢复不得迁移、覆盖或清空既有应用数据目录、供应商配置或密钥引用；源文件路径变化时仅可按已记录的视频指纹重新绑定，禁止同名猜测。独立样本集及隐藏验收集与用户数据、发布产物隔离，禁止自动清理或打入正式安装包。 |

| CLIP-037 | 增量实施的故障诊断、批量修复与打包节奏 | 原剧切片的新引擎必须按可独立验收的关卡替换旧流程；旧候选标记 `engine=legacy` 并保持可读、可审阅和可导出，新候选使用独立 `engine=evidence-v2` 证据包与快照，禁止原地迁移、混用新旧逻辑或在用户任务中长期双跑。每个关卡先运行完整的相关测试矩阵；每个场景必须从独立初始状态/夹具启动，使一个按钮或上游路径失败不遮蔽后续独立场景，连续真实路径另作为单独集成用例。测试执行不得遇到首个失败就停止，须收集全部可独立发现的失败；因上游故障不能执行的用例必须标为“被上游阻断”，上游修复后重跑整个相关矩阵。任何“根因”只可作为带最小复现、可证伪预测和预期受影响/不受影响用例的诊断假设；修复后必须验证预测，未出现预期改善即停止沿该假设继续堆代码，重新诊断。测试污染、陈旧缓存或配置、夹具错误、异步竞态、业务缺陷和需求或合同冲突必须分开归类；需求或合同冲突不得以实现侧猜测解决，必须回写 Product-Spec 裁决。已证实且职责相近的根因可在同一修复批次内处理，但不得把未验证假设混入大补丁；多个修复批次之间只运行本地构建和相关矩阵，修复必须补充回归用例。安装包不是每个失败或修复的验证单位：仅在完整关卡集成通过后生成一次功能验证包，以验证 Electron、迁移、真实 IPC、媒体等开发态覆盖不到的路径；所有关卡整合通过后再生成正式候选包，运行隐藏集、全量回归、压力与打包验证。短期内部路由开关只服务无损回退和验证剧集，不得成为用户长期选项；新引擎正式替换后必须移除旧分支和开关。 |

**用户流程：**

1. 操作者从已导入原片进入切片台，先看到所有分集的明确生产状态和“生成候选切片”主操作；选择一个或多个分集后，先看处理量、预计候选数、重合约束和可跳过项，再开始生成。
2. 生成完成后，操作者在“全部候选池”查看各集独立候选，或从“源分集”定位某集；选中候选后，监视器、源分集时间线与候选片段时间线联动。任一时间线交互只用于暂停定位；仅右侧四个 0.1 秒微调按钮可以修剪边界，之后执行唯一的“确认候选”动作；不得把“审阅”和“确认”做成两个重复关卡，也不得把多剧集候选串成自动拼接的成片。
3. “生成候选”与“导出”是两件事：确认后的独立候选进入待导出池；操作者选择一个或多个候选，检查目录、命名、编码/尺寸、字幕策略和预计体积后启动导出。导出任务与成果库可追溯，失败可重试，源片不被修改。

| ALIGN-001 | 逐集候选池 | “全部候选”是原剧切片工作区的第二阶段，不是把全部分集候选堆在同一长列表。左侧为源分集，候选区只渲染当前选中分集的窗口；“全部”仅表示该分集内不按状态过滤，不表示全部剧集。多分集可各自生成独立候选，但不会自动堆叠为跨集序列。候选区支持全部、待确认、已确认、已导出筛选和候选编号/源时码搜索。当前分集标题、剧集状态、当前窗口和独立输出语义必须可见；压力基线仍为至少 5,000 候选/500 待导出，但 DOM 只保留可见窗口与缓冲。 |
| ALIGN-002 | 原剧切片完成报告 | 原剧切片必须有与候选工作区同属一个模块的第三阶段“完成报告”，而不是导出后直接跳转成果库。报告按本次任务分集固定左栏，主区显示本集汇总、候选结果、异常/继续处理入口和选择/悬停反馈；结果区须有“本集输出明细”及候选、源片区间/真实输出文件、时长、状态、操作的列头，不能让长列表只能靠位置猜字段。所有返回统一到素材生产，成果库只是明确的后续回链。 |
| ALIGN-003 | 导出状态与真实回链 | 导出仍由候选池发起，预检/配置/进度使用真实数据；完成后进入原剧切片完成报告，报告内可显式打开成果库。导出配置、失败重试、取消和原片保护维持 CLIP-005 的既有边界。 |
| ALIGN-004 | 字幕资产列表与详情弹窗 | 字幕资产首屏是按分集归档的紧凑列表，含资产、状态和“查看画面/状态”。详情在焦点可控的模态框内展示完整 `contain` 源画幅、OCR 区域、ASR/OCR 对齐差异和独立滚动的证据队列；不再在首屏并列堆叠三栏证据。需覆盖未导入、识别中、待校验、已校验、媒体缺失及三分钟/90 条证据压力态。 |
| ALIGN-005 | 字幕批量入口与设置 | 列表工具栏提供“一键生成字幕”“导入字幕”“字幕识别设置”。一键生成按选择范围创建真实 ASR/OCR 任务或明确显示本机引擎未就绪；不得伪造准确率、费用或成功。设置以模态草稿保存识别范围、语言、ASR/OCR 方式、差异阈值与导入策略；导入策略只能影响证据归档或人工校验，不得出现无实际行为的“仅作为展示字幕”，也不把剪辑展示字幕塞回资产页。 |
| ALIGN-006 | 视觉与交互忠实度 | 以上改动必须复用最终原型的石墨深色、暖沙橙焦点、细线分隔、6/9px 圆角、列表行 hover/selected 与图标关闭语义；不得恢复蓝色占位、浏览器默认滚动条、早期三栏字幕工作台或跨集候选长列表。1440×900、1280×720 无横向溢出，主任务不被固定栏遮挡。 |
| ALIGN-007 | 监视器故障降级与画幅保真 | 每个剧集持久化 FFprobe 返回的宽、高；工作台和字幕详情把该元数据传入监视器。媒体 `error`、缺路径、未选中和读取中均保留最后已知画幅（无元数据时才默认 16:9）、时间码和可辨识的暖色场景骨架；重新关联到不可读、无权限或损坏路径时，更新源路径、状态、时长与帧率，但不得清空已有宽高。缺媒体在工作台与字幕详情均明确给出可执行的“前往剧目资产重新关联”处置入口。`sourcePath` 缺失且调用方仍传入 `ready` 时必须安全降级为缺媒体，不能渲染时异常。不得以小暗框、纯色块或默认 16:9 替代。必须覆盖 16:9、9:16、空路径与真实不存在/损坏文件触发的 Electron 故障路径。 |
| ALIGN-008 | 全局剧目库导航退出 | 无论当前处于剧目资产、素材生产、候选工作区、完成报告或字幕资产，点击应用壳左侧“剧目库”必须回到剧目库根列表并清除当前剧目工作区选择；不得只改变侧栏高亮/顶部面包屑而继续显示旧工作区。退出只影响当前剧目选择，库根页已输入的搜索、标签筛选、排序、视图和未提交创建草稿不得因点击全局入口而丢失。再次从列表打开剧目必须重新读取该剧目的最新持久化数据。 |
| ALIGN-009 | 切片工作区渐进披露 | Version 48 原剧切片默认态的中心画布必须优先呈现监视器、源分集状态、双时间线和当前候选确认检查器；低频生成参数只在生成前入口或预检状态出现，候选内字幕优化不能以长表单或常驻按钮列挤压检查器。默认候选检查器依次突出候选上下文、左右微调、重合提示、全部候选池和确认；字幕展示优化/资产入口保留为按需展开的次级操作，剧目级字幕资产仍从独立标签可达。默认三栏比例、紧凑分集行、暖色监视器占位和细线分隔必须保留。 |
| ALIGN-010 | Version 48 应用壳与首屏密度 | 最终静态原型的左侧应用壳、顶栏和内容内边距属于 SCREEN-005 的组合基底，不能因沿用旧生产壳而挤压工作台。≥1301px 时侧栏为 220px、顶栏为 56px；1280×720 时侧栏按原型收缩为 72px 图标导航。切片首屏必须完整呈现监视器 → 当前候选片段时间线 → 源分集时间线，不以主页面滚动或放大固定边栏掩盖差异。此项是对既有应用壳的嵌入式调整，保持全部全局导航、通知和键盘滚动行为。 |
| ALIGN-011 | 候选池的模块标题、阶段与状态层级 | `screen-clip-pool` 仍属于“原剧切片工作区”：页面标题、面包屑和返回语义必须保留该模块名；“全部候选”只能作为第二阶段标识和候选区标题，不能替换整个工作区标题或制造一个独立工具页。左侧源分集须由真实媒体和候选数据明确区分未生成、待确认、已确认、导出中、已导出、异常与媒体缺失，右侧待导出队列须显示对应真实计数；候选池继续按当前源分集窗口化，不以标题或汇总暗示跨剧集候选会被拼接。候选默认行严格保留原型的编号、源时码、时长、状态与“打开”，不得常驻复选框；批量导出选择移至“配置并导出”的按需抽屉，默认预选全部已确认候选，支持逐项取消并在预检中只使用该次选择。 |
| ALIGN-012 | 可追溯的完成报告回链 | 候选池的“查看完成报告”只能打开最近一次真实完成导出批次所包含的 candidate ID，批次需持久化所选候选、创建/完成/取消/失败状态、时间和失败原因；不得以全剧历史已导出候选、当前筛选结果或内存临时数组拼成报告。单候选、批量和失败重试均创建真实批次。同一 candidate ID 不得重复进入配置，且须以原子状态抢占和持久化批次所有权阻止并发 FFmpeg 导出；取消、失败、成功和应用重启恢复只可释放或完成本批次仍持有的候选，遗留运行批次必须真实标记为取消。无已完成批次时，入口必须解释不可用原因而非跳转空报告。 |
| ALIGN-013 | 完成报告阶段上下文 | 完成报告仍属于原剧切片工作区的同一阶段导航，必须显示 Version 48 的三阶段上下文：1 候选工作区、2 全部候选、3 完成报告。导出是“全部候选”阶段内的真实导出抽屉，不得伪装为独立阶段或新建孤立导出页。报告主体继续只显示本次批次 candidate ID。 |
| ALIGN-014 | 工作台首屏可见性 | 在 1440×900 与 1280×720，原剧切片工作台的监视器、当前候选片段时间线和当前源分集时间线必须同时完整落在应用可见视口内；阶段导航须保持 Version 48 的分段边框与暖沙橙活动态，不得退化成挤压媒体画布的松散标签栏。以真实 Electron 元素边界和同状态截图验收，不能以主页面滚动后的截图代替。 |
| ALIGN-015 | 字幕详情优先加载与本地 OCR 可达性 | 字幕资产首屏的全剧集状态汇总不得阻塞已选分集详情：详情的轨道、画幅、OCR 区域、质量与可用性须独立优先读取；90 集或慢速列表读取期间，详情只能显示自身的加载/错误态，不能误标未导入或等待全表结束。任一核心证据读取失败时，两侧证据列和结论区必须显示读取错误，不得把空回退值渲染为“未导入”。全表请求和详情请求均须以请求 ID/分集 ID 隔离过期响应。最终静态原型只有列表工具栏的“一键生成字幕”，详情模态没有“提取画面 OCR”控件；不得为满足功能臆造详情按钮。详情选中的剧集在关闭弹层后仍是“当前剧集”，操作者可通过该已有工具栏入口按已保存范围触发本地 OCR。执行失败如实显示原因、成功后刷新列表与仍打开的详情的独立 OCR 证据，不覆盖 ASR 或导入轨。 |
| ALIGN-016 | 切片工作区异步证据与状态真实性 | 原剧切片工作区的分集生产状态、当前候选的 ASR/OCR/导入轨与展示字幕变体必须分别拥有 `loading → loaded | error` 状态。状态汇总读取失败时，源分集不得回退显示“未生成”；当前候选字幕读取失败时，字幕编辑弹窗必须显示读取错误，不能用“先建立证据”或空变体伪装真实结论。切换候选/分集或重复刷新时，过期响应不得覆盖当前候选；状态失败不阻塞监视器、双时间线和可独立完成的候选操作。 |
| ALIGN-017 | P1 二创能力状态真实性 | 爆点前置二创读取文本分析/视频理解能力状态时，必须拥有 `loading → loaded | error` 状态和可达重试。读取失败或运行时缺少能力查询 API 时，页面不得把空数组解释成“已保存供应商配置”或“已配置全部能力”；必须如实说明当前无法确认配置，同时保持已有受控本地分析路径可操作。过期读取不得覆盖当前页面状态；此项不新增云端执行、P2 解说/TTS/旁白入口或任何 provider 可达面。 |
| ALIGN-018 | 导出进度批次隔离 | 候选池导出抽屉的轮询、取消与重试必须只更新当前 `exportId`。启动新批次、关闭抽屉或切换至完成/失败状态后，旧轮询及其成功/失败文案不得覆盖当前进度或消息；进度读取失败必须只标记对应当前批次，不能伪造完成。 |
| ALIGN-019 | 候选池视觉骨架与返回语义 | 以 Version 48 `screen-clip-pool:default:1440×900` 的项目库预览为裁决：候选池必须保持既有真实筛选、选择、窗口化与导出行为，但中央候选行依次呈现稳定候选序号、源时码区间/来源、独立时长、真实状态和“打开”操作，不能以 UUID、常驻说明、高行距或当前分集已在工具栏明确后再次出现的重复组标题破坏原型的高密度列表。候选编号由持久化创建顺序确定；新一轮生成不得重排已有编号，候选编号（含 `C-xx`）与源时码均可搜索。左轨、候选主区和待导出检查器必须使用原型的石墨深色面板、细线分隔和紧凑行距。顶部“返回素材生产”必须回到素材生产，阶段栏“1 候选工作区”仍只进入同模块第一阶段。不得删除键盘可达的选择控件、当前分集窗口化、5,000 候选压力边界、真实导出及报告回链。 |
| ALIGN-020 | 批量生成后的源分集联动 | 批量生成成功后，工作区必须把首个实际生成候选作为当前候选，并同步切换“当前源分集”。监视器、源分集时间线、候选片段时间线、左侧激活行和检查器不得分别停留在旧集与新候选；若本次没有生成候选，则保持原选择并如实显示生成结果。该联动不得改变候选独立输出、低重合约束或批量生成的多集语义。 |
| ALIGN-021 | 候选池到报告的单一出口 | Version 48 的候选池右侧检查器只承载“配置并导出”和最近真实完成批次的“查看完成报告”。候选池不得额外提供“打开成果库”而跳过第三阶段；成果库继续仅作为完成报告的显式后续动作。无真实完成批次时，报告入口保持不可用并说明原因，不以成果库替代报告。 |
| ALIGN-022 | 素材生产页的 P2 视觉冻结 | 以最终 Version 48 的覆盖脚本为准：素材生产只展示原剧切片、多集拼接、爆点前置二创三项生产方法，方法标签依次为“人工审核 / 批量处理 / AI 辅助剪辑”，卡片说明与入口分别为“准备字幕、生成候选并人工审片微调，确认后统一导出到成果库。/ 进入工作区”、“按滑动窗口批量组合连续剧集，预检时长、体积、帧率和包装后运行。/ 创建拼接任务”、“基于字幕、分镜和剧情分析生成可解释草稿，必须经过人工审核。/ 查看工作台方向”。原型早期的 P2 未来卡已被终版移除；生产页不得保留“AI 短剧解说”卡、禁用按钮或其他视觉入口，更不得新增 P2 路由、preload、IPC、provider、任务或成果。 |
| ALIGN-023 | 剧目库的 Version 48 整页结构 | 剧目库必须保持最终原型的页头、搜索/标签/排序工具栏、三列卡片/同卡片列表切换与每页六项分页；卡片只呈现封面、名称/资产状态、集数与标签、更新时间和真实最近任务。不得添加页头总数、卡片底部编辑操作、任务/资产摘要 rail 或无来源表格壳。真实封面、创建/导入、筛选/排序、分页、工作区打开和编辑可达性必须保留；编辑入口位于剧目工作区。原型未覆盖的全空库、加载和读取错误状态须先获得 Open Design 可预览依据才能改动视觉。 |
| ALIGN-024 | 剧目资产与工作区的 Version 48 整页结构 | 剧目资产默认态必须保留剧目上下文、返回/编辑、资产/素材生产/字幕资产/成果库标签、四格健康概览、添加剧集/批量重新定位/导入剧本/状态筛选以及集号、文件、时长、帧率、剧本、状态、操作七列资产表。`字幕资产` 是终版脚本注入且已有独立真实功能的标签，不得为贴早期三标签片段删除；文件夹导入、删除应用内剧集引用和剧本预览是已规格化真实扩展，保留但不得挤占原型默认工具栏和表格首屏。剧目代号、加载、全空、脚本导入失败、缺媒体、长列表与删除确认均没有完整 Version 48 逐态依据，未获 Open Design 可预览状态前不得自由改造其视觉；真实路径、原片保护、自然排序、85 集滚动和重新关联必须保留。 |
| ALIGN-025 | 多集拼接真实完成报告 | `screen-stitch` 的第 4 阶段必须读取当前剧目作用域内 `multi_episode` 任务的真实 `TaskSummary` 与 `TaskReportItem`，以成功、缩减、跳过、失败、取消的真实项数和本次输出明细渲染，不能把“任务创建”或 `onRunTask` resolve 伪装成任务完成。任务指针必须按 dramaId 持久化，并在重开工作区时校验 taskId、dramaId、type；无效指针立即清除，禁止猜测“最近任务”。只有真实终态 `completed`、`partial`、`failed`、`cancelled` 才能进入第 4 阶段和读取报告；运行/暂停仅显示真实状态并持续刷新。报告只展示当前 task ID；成功项可显式进入该剧成果库，失败项保留真实原因并可到任务中心处理。取消保留已完成成果且报告如实显示，不回滚或填充原型示例数量。报告读取失败独立呈现真实错误与重试，不得改写任务结果；运行、失败、取消等非默认视觉状态仍须先取得 Open Design 可预览依据后再做视觉美化。 |

### 10.25 字幕三种识别方式与真实执行（新增，2026-08-05）

“一键生成字幕”必须由字幕识别设置中的顶层“识别方式”决定，不能再把 OCR 当作默认或唯一执行路径。可选方式为 `仅 ASR（音频识别）`、`仅 OCR（画面字幕识别）`、`ASR + OCR 双重识别`。这是字幕资产页内部的设置与执行变化，不修改剧集列表、字幕导入、查看画面/状态、删除、其它工作区或供应商配置页面。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-MODE-001 | 原型与可见字段 | 新增模式三段选择必须先写入独立静态原型版本，并直接作为字幕 iframe 的原型来源。选 `仅 ASR` 时只显示 ASR 细项；选 `仅 OCR` 时只显示 OCR 细项；选双重识别时同时显示。识别范围、语言、差异阈值和导入策略保持原有原型位置与语义。 |
| SUB-MODE-002 | 仅 ASR | 针对识别范围内有可读媒体的分集，使用当前 `asr` 默认供应商生成独立 ASR 原始证据轨。首个真实执行器为腾讯云 ASR：主进程使用已安全保存的 `SecretId + SecretKey` 做 TC3 签名；本地视频先经 FFmpeg 生成临时 16 kHz 单声道音频，按腾讯 `CreateRecTask` 的 `SourceType=1`、未编码音频小于等于 5 MB 的官方限制切段上传并轮询，完成后按原始时间轴合并 cue。不得从 Renderer 读取或返回凭据，不上传视频帧，不记录音频内容、签名、密钥或原始响应。其它默认 ASR 供应商尚未有执行器时必须如实阻止，并说明要切换到已可执行的腾讯云 ASR 或稍后接入该供应商，不能假装已生成字幕。 |
| SUB-MODE-003 | 仅 OCR | 本地 OCR 必须独立从可读媒体按固定采样间隔抽取固定字幕区域并合并相邻重复文本，直接生成 OCR 原始证据轨；不得要求已有 ASR、导入字幕轨或云端配置。Tesseract、FFmpeg、语言选择或固定 OCR 区域缺失时，准确列出前置条件，不能创建空轨或改写现有 ASR/导入轨。 |

| SUB-MODE-005 | 范围、幂等与结果 | `当前剧集` 没有已选择分集时必须阻止；`全部` 与 `仅缺失` 逐集执行并返回真实成功/跳过/失败数量。每次成功运行新增可追溯原始轨，不覆盖导入字幕或历史 ASR/OCR。运行中禁止重复启动同一次生成；本次范围无可处理媒体时不得产生轨或成功提示。 |

**验收场景：**

- Given 腾讯云 ASR 草稿有完整的双凭据，When 用户点击“测试当前配置”，Then 可看到一次真实签名验证的成功或分类失败与耗时，且无业务素材上传、无任务创建、无 profile 或密钥写入。

- Given 已保存双凭据而当前两框为空，When 点击测试，Then 仅主进程从既有安全引用读取两项；界面不回显任一值。

### 10.26 字幕三源时间窗对照与播放定位（新增，2026-08-05）

在线 ASR、用户导入的 SRT/VTT 与 OCR 是三个独立证据来源；三者各自的分段数量、起止时间与文本都可能不同。导入字幕不再作为 `ASR（导入）` 混入 ASR 列，必须以独立来源展示。此需求取代 `SUB-002`、`ALIGN-004` 与 `SUB-REAL-008` 中“导入字幕归入 ASR 左侧列”这一展示约定；原始 `source_kind='import'` 数据和既有导入/删除契约不迁移、不改写。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-COMPARE-001 | 三列来源 | “查看画面”的右侧只读证据区按 `在线 ASR`、`导入字幕`、`OCR 字幕` 三列展示；列头、缺失态与每个文本单元的来源必须可辨认。在线 ASR 与导入字幕即使同时存在也不得合并、覆盖或互相改名；OCR 仍只展示真实 `source_kind='ocr'` 轨。 |
| SUB-COMPARE-002 | 时间窗而非序号配对 | 每一行是一个按时间排序的对照时间窗，不是三份字幕的第 N 条。仅当 cue 的时间区间实际重叠时才进入同一行；无重叠或缺少来源时该单元显示“—”。不得根据相似文案猜测配对，不得自动整体平移任一来源的时间码，也不得伪造差异/一致结论。每个非空单元保留该来源 cue 的原始起止时间。 |
| SUB-COMPARE-003 | 点击定位 | 点击任一非空字幕文本单元时，左侧当前剧集视频必须跳到该单元所属 cue 的原始 `startSeconds`，同步刷新现有播放头与当前时间码；点击不播放/暂停、不改变范围、不写数据库、不生成或修改字幕、不改变其它列的选择。视频不可读、cue 时间非法或超出视频时长时，保持当前位置并在原位置如实提示，禁止跳到另一来源的近似时间。 |
| SUB-COMPARE-004 | 原型与滚动边界 | 三列对照、可点击单元及定位状态必须先在字幕静态原型中完成并确认，再按静态原型迁移规则接入运行时。右侧证据区仍是唯一可滚动区域；弹层主体、左侧视频与时间线不得因此变为页面级或详情级滚动。不得改动导入入口/删除、识别设置、剧集列表、压力样本、供应商配置或其它工作区。 |

**验收场景：**

- Given 同一分集的在线 ASR、导入字幕和 OCR 各有不同数量与不同时间码的 cue，When 打开查看画面，Then 三列独立显示，任一来源不会被当作另一个来源，且不存在按序号强行拼成同一行的结果。
- Given 导入字幕 `00:01.20–00:02.10`、在线 ASR `00:01.40–00:02.30`、OCR `00:04.00–00:04.70`，When 展示对照，Then 前两者可处于同一时间窗，OCR 必须处于另一行；缺失的列显示“—”。
- Given 用户点击 OCR 单元，其 cue 起点为 `00:04.00`，When 视频可读，Then 视频与播放头定位到 `00:04.00`，且没有自动播放、范围播放、设置保存或字幕数据写入。

**非目标：** 本期不做全局时间码校准、自动文本相似度配对、合并/覆盖三份原始字幕、冲突编辑、范围播放、自动播放或跨剧集联动。

### 10.30 字幕查看画面的右侧实时只读联动（新增，2026-08-06）

“查看画面”的右侧三源证据区完成真实只读闭环：它只反映当前已读取的三份原始 cue 与左侧当前视频的播放位置，不引入原型压力样本的“演示状态”切换，也不把来源存在与否伪装成校验结论。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-RIGHT-001 | 当前播放定位 | 左侧视频的 `loadedmetadata`、定位、拖动时间线、前后 5 秒与播放过程均应将当前秒数通知右侧。右侧只把时间覆盖当前秒数的真实 cue/时间窗标为当前；一个时刻命中多个来源时可同时标出。不得据此写入数据库、改变来源、自动播放或自动滚动证据区。 |
| SUB-RIGHT-002 | 选择与当前分离 | 用户点击 cue 后，保留原型既有“已选择”外观并按该 cue 的原始起点定位；播放进度产生的“当前”标记不得清除用户的选择，也不得把其它 cue 改成已选择。定位后的状态文案如实说明当前位置及是否正在播放。 |
| SUB-RIGHT-003 | 真实时间窗归属 | 每个运行时生成的时间窗和 cue 必须保留原始起止时间及来源标识，供当前定位判断和无障碍描述使用；没有任何来源覆盖当前秒数时，右侧明确保持无当前 cue。不得显示或启用 `演示状态`、三源样例切换、文本相似度判定、一致/冲突结论或人工写入入口。 |

**验收场景：**

- Given 一个时间窗内有导入 cue `00:01.20–00:02.10` 和在线 ASR cue `00:01.40–00:02.30`，When 视频定位到 `00:01.50`，Then 两条 cue 与该时间窗均标为当前，且视频保持暂停。
- Given 用户点击 OCR cue 后再将视频播放到另一条 ASR cue，When 右侧接收播放进度，Then OCR 仍是已选择，ASR 仅作为当前播放 cue 标出；右侧滚动位置不被程序抢夺。
- Given 当前视频位置不落在任何 cue 的原始时间区间，When 播放进度更新，Then 右侧没有当前 cue，且不产生新的校验结论或数据写入。

**非目标：** 本期不修改右侧的列数、滚动容器、原型视觉网格、导入/删除、识别设置、剧集列表、查看状态、压力样本、供应商配置或其它工作区；不做自动滚动、编辑、接受/驳回、校验结果持久化或播放范围。

### 10.31 OCR 独立时间轴与本地引擎基准（新增，2026-08-06）

OCR 的职责是读取画面硬字幕，不是给 ASR 补字。OCR cue 的起止时间必须来自视频画面中字幕的实际出现与消失，而不是 ASR/导入 cue 的起止时间、文本相似度或索引。当前 Tesseract 单帧实现仅作为待比较候选，未取得真实短剧样本验证前不得表述为最终 OCR 方案。

本期已完成两轮本地引擎基准，结论仍为**继续评估检测器 + 识别器分层方案，不接入任何候选**。VSE/VideoSubFinder 可在隔离目录作为研究候选运行，但其实际分发内容包含 GPLv2 检测器与来源未完整审计的 DLL，当前没有获准的产品分发路径；其原始 Windows runner 也出现时间错位。RapidVideOCR 的视频路径依赖 VideoSubFinder，RapidOCR 的模型分发条款未被证实。Tesseract.js + OpenCV 两次同样本 POC 可独立产生时间段，但标题、普通对白识别错误且 Python OpenCV wheel 的实际发布路径未审计，未达到接入门槛。完整证据见 `docs/research/ocr-engine-benchmark-2026-08-06.md`。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-OCR-ENGINE-001 | 独立时间轴 | OCR 引擎必须先从视频画面检测字幕时间段，再为每个画面时间段识别文字并合并连续重复文本；不得由 ASR/导入 cue 决定 OCR 的抽帧点、段起止或是否跳过一段。ASR 只可在 OCR 轨生成后参与只读对照。 |
| SUB-OCR-ENGINE-002 | 同样本基准 | 对同一真实短剧分集、同一固定字幕区域和同一输出格式，运行每个本地候选。报告必须记录候选版本/提交、许可证、运行方式、总耗时、输出 cue 数、人工抽查的漏字幕/错字/时间码问题和失败日志摘要；分发资格未审计完成的候选只可留在隔离研究目录，不得打包或接入。不得以宣传页、模拟 cue 或不同视频样本替代。 |
| SUB-OCR-ENGINE-003 | 候选边界 | `YaoFANGUK/video-subtitle-extractor` 的实际分发内容包含 VideoSubFinder 组件，允许隔离研究但当前没有产品分发或适配器接入资格。`RapidVideOCR`、`PaddleOCR` 与 `Subtitle Edit` 仅按调研文档中的检测/识别/参考用途评估。任何源码复用、二进制分发或嵌入前必须单独完成许可证、Windows 打包体积、中文路径、模型下载、离线运行和安全边界审查。 |
| SUB-OCR-ENGINE-004 | 结果契约 | 基准引擎的输出先转换为本工具已有的独立 `source_kind='ocr'` 轨和 cue 契约；不得覆盖 ASR、导入字幕、用户源视频或现有 OCR 轨。候选不产生可解析的独立时间码与文本时，即视为不满足接入条件。 |
| SUB-OCR-ENGINE-005 | 失败与隐私 | 本地候选引擎缺失、模型/语言包下载失败、GPU/CPU 不兼容、视频路径不兼容、区域未设置或运行失败时，只记录并展示真实原因；不得静默转云端、上传视频、退化为 ASR 时间锚点或创建成功轨。 |
| SUB-OCR-ENGINE-006 | 剧目级字幕区域校准 | OCR 字幕轨的第一判据是当前剧目已确认的字幕区域，不是识别文字的语义。系统可从当前剧目的代表画面提出一个或多个字幕区域候选；操作者必须能在视频画面上查看候选、选定一个候选，并通过可拖动/可缩放的框精确调整后确认。确认区域按剧目保存并用于该剧全部剧集；本期不做逐集区域覆盖。 |
| SUB-OCR-ENGINE-007 | 区域边界优先 | 只对已确认字幕区域内的文字做时间检测和 OCR；区域外的人名、身份条、地点/时间牌、场景文字都不扫描、不识字、不写入 OCR 字幕轨。不得以“像对白”“像标题”或其它语义猜测替代区域边界。`未完待续` 是唯一已确认的首期输出排除项：即使出现在区域内，也只按规范化精确匹配排除，不引入泛化的标题/场景文字分类器。 |

**基准通过条件：**

- 同一实际画面中存在但 ASR 没有对应 cue 的硬字幕，OCR 候选仍能生成其独立的时间段和文本；反过来，ASR cue 不存在不能让 OCR 时间段消失。
- OCR cue 的出现/消失时间由画面检测结果产生，能够在“查看画面”右侧与 ASR、导入字幕以真实时间关系独立呈现，而不是按序号或 ASR 时间硬配。
- 对同一剧目先完成区域候选、人工确认与微调；确认后区域外出现的任何文字均不得进入 OCR 字幕轨，区域内的 `PUA / 凌辱 / 家暴` 等叙事硬字幕必须保留。每部新剧必须独立校准，不得把上一剧的区域静默带入。
- 基准结论已明确为“不接入，继续验证检测器 + 识别器分层方案”。在新的候选用同样本同时证明独立时间段、可解析文本、Windows 可复跑、许可证可接受和可解释失败前，不得改动现有 OCR 执行器、静态原型、供应商配置或批量任务行为。

**非目标：** 本期不实施任何候选引擎接入、不安装或分发候选工具、不改变现有字幕识别设置和界面、不执行全剧批量 OCR、不接入云端 OCR、不改右侧三源对照、导入/删除、ASR、剧集列表、查看状态或其它工作区；人名/身份等剧情视觉标识的独立采集与剧情分析另立需求，不随字幕区域校准一并开发。

### 10.35 已校准区域本地 OCR 的单集时限基准（新增，2026-08-06；时限更新于 2026-08-10）

本地 OCR 的当前实现已能从已校准区域独立产生时间轴，但同样本实测显示：亮度掩码会把区域内的无字幕画面变化送入完整 OCR，且当前逐帧串行识别会超过可接受的单集等待时间。本轮只优化本地执行器，不改变字幕资产页、三源对照、识别批次、ASR、导入字幕、供应商配置、数据库结构或静态原型。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-LOCAL-OCR-001 | 校准区域只读 | 本次执行只读取当前剧目已确认的 OCR 区域；不得自动收窄、扩张、覆盖或写回该区域。区域内文本是否为字幕仍只由操作者确认的几何边界决定，不引入词义过滤。 |
| SUB-LOCAL-OCR-002 | 检测与识字分层 | 使用 PaddleOCR 官方文本检测与文本识别能力分层处理：先判定候选图中是否存在文本框，再只识别有文本框的候选。无文本结果不得创建 cue；`未完待续` 继续只按精确规范化匹配排除。 |
| SUB-LOCAL-OCR-003 | 批量与时序 | 文本识别应以有限批次处理候选图，OCR cue 的时间段继续严格来自本地视频检测，不能读取 ASR、导入字幕或云端结果。相邻重复文本仍只按既有时间与相似度规则合并。 |
| SUB-LOCAL-OCR-004 | 单集硬上限 | 自本地 OCR runner 开始计时，单集在 420 秒内必须返回完整成功结果或明确失败；超过 420 秒立即结束并返回可理解的超时原因。超时、检测失败、识别失败或无可解析 cue 时，服务端不得创建 OCR 轨、不得覆盖既有 ASR/导入/OCR 轨。 |
| SUB-LOCAL-OCR-005 | 同样本验收 | 必须使用当前剧目第 01、43、85 集、同一已保存区域完成实测。每集记录总耗时、采样帧数、候选数、检测到文本的候选数、实际识别数、cue 数，以及人工核验的误入文字、漏识和时间码现象。仅三集均不超时且没有区域内无关文字写入时，才允许用既有“识别已选 1 集”创建新的正式 OCR 轨。 |

**非目标：** 本轮不自动修正用户已保存的校准框、不新增“试运行”轨道或局部结果展示、不把抽样诊断结果写入字幕资产、不改识别按钮、任务进度、页面布局或任何云端 OCR 路径。当前以本机使用为前提，不针对低配置电脑新增兼容模式、动态超时、性能分级或降采样策略；单集实际耗时会随 CPU、GPU、内存和磁盘性能变化，留待未来独立需求评估。

### 10.36 宽字幕候选区内的字幕行选择与时序跟踪（新增，2026-08-07）

用户确认的剧目级 OCR 区域是宽的候选边界，不是“框内每个文字框均为字幕”的判定。执行器必须先从该边界内的 Paddle 文本检测框构造候选文字行，再用文字框的几何关系、视觉样式和跨帧连续关系选择字幕行，最后才对选中行识字并形成独立 OCR cue。字幕行可以延展到候选区的完整宽度；不得通过收紧左右边界牺牲长文本。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-LOCAL-OCR-006 | 宽区只作候选边界 | 已保存的 `x/y/width/height` 只限定图像检测范围，执行器仅读取，绝不自动收窄、扩张或写回。框内检测到的全部文字框不能直接拼接成一条 OCR cue。 |
| SUB-LOCAL-OCR-007 | 字幕行选择 | 以检测框的垂直重叠、基线、间距、尺寸/视觉特征及跨帧位置与持续性构造并选择字幕行；仅将被选中的行框送入文本识别，并按该行的视觉阅读顺序合并。不得使用文本词义、文字语言/字符集、品牌词黑名单、ASR、导入字幕或其它外部时间码决定取舍。 |
| SUB-LOCAL-OCR-008 | 时序独立 | 字幕行出现、变化、消失及 cue 合并仍只来自当前视频画面。画面内服装、道具、场景或台标文字即使落在宽候选区内，也不得因“被检测到”直接进入 OCR cue；无法用视觉与时序规则判定时必须如实失败或留作隔离诊断，不得写入正式轨。 |
| SUB-LOCAL-OCR-009 | 真实验收集 | 使用当前剧目第 01、43、85 集。第 01 集需保留正常对白；第 43 集不得输出服装上的 `MOXINXIN / TEXAS / DALLAS / BLACKAIR / RollingPaper` 或其 OCR 变体；第 85 集必须识别出默认框未覆盖字幕带，并在不改写已保存区域的前提下生成独立 OCR cue。三集隔离基准绝不写库，全部通过并在 420 秒内返回后，才可用既有选集识别路径写入一集正式 OCR 轨。 |

**非目标：** 本期不新增或改造校准页、字幕资产页面、三列证据区、ASR、导入、供应商、任务状态、数据库结构或云端 OCR；不嵌入、复制或分发 VideoSubFinder、RapidVideOCR 等外部实现。成熟工具仅作为“画面检测、字幕行选择、OCR 分层”的研究参考，许可证与发布路径另行审计。

### 10.37 已选字幕行的局部时间边界细化（新增，2026-08-07）

现有本地 OCR 以 5fps 全片粗扫建立候选段，因而 cue 起止只能落在 0.2 秒栅格。本期先保留既有代表帧识字与相邻同文本合并，再仅在已合并 cue 的首尾边界做局部细化；不得在合并前按单个粗候选反复切段，也不以提高全片采样率替代局部复核。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-LOCAL-OCR-010 | 先合并，再校准边界 | 全片候选仍维持 5fps，既有代表帧识字和相邻同文本合并先完成。仅在被选中字幕行构成的已合并 cue 首尾各最多 0.2 秒，以 25fps 读取局部画面；局部参考只能来自同一 cue 首尾已选字幕行的画面，且只可校正 cue 两端，不得检查或切断 cue 内部连续区间，不得扫描全片 25fps。 |
| SUB-LOCAL-OCR-011 | 原始画面时间轴 | cue 起止只能由当前视频中局部复核得到的画面时刻产生。不得使用 ASR、导入字幕、文字词义、语言、品牌词或其它外部时间码校正时间；不得改写校准区域。 |
| SUB-LOCAL-OCR-012 | 代表帧与文本稳定性 | 本期保持原有代表帧识字路径和文本合并结果；时间边界细化不得重新选帧、重新识字或改变 cue 文本、数量、合并关系。该约束避免画面时间校准反向改坏 OCR 文本。 |
| SUB-LOCAL-OCR-013 | 性能与回退 | 单集仍须在 420 秒内完整成功或明确失败。仅当边界窗口中存在跨过原粗边界的连续视觉证据时才调整该端；任一端证据不足即保留原始粗边界，不创建虚假的精细时间码；任何超时或失败均不得写入 OCR 轨。 |
| SUB-LOCAL-OCR-014 | 同样本复验 | 对第 01、43、85 集同一区域重新隔离运行：第 01 与 43 保留正常 cue，43 的服装反例仍零命中，85 仍无 cue。输出粗候选与细化后时间码的差异统计；只有性能不回归到 420 秒外、三集边界均满足原有结果约束时，才允许沿用正式路径。 |

**非目标：** 本期不增加时间码手工编辑、逐帧预览、时间轴 UI、可配置帧率、范围播放或新的持久化字段；不重新识别已有正式 OCR 轨，不修改 ASR、导入字幕、供应商、字幕资产列表、查看画面、校准页及任何静态原型。

### 10.38 剧集字幕带预检与真实出现帧（新增，2026-08-07）

剧目默认框是用户确认的优先边界，但不能被当作所有分集字幕位置一致的证明。每集 OCR 先以低频全画面文字检测提出只读的字幕带候选；候选已覆盖默认框时仍使用默认框，只有默认框未被候选充分覆盖时，才在本次运行临时使用该集候选带。候选带必须保持全宽，不自动写入、收窄、扩张或覆盖用户保存的区域。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-LOCAL-OCR-015 | 剧集级只读预检 | 每集在正式 OCR 前进行低频全画面 Paddle 文本检测，形成稳定文字行的全宽垂直候选带。候选覆盖已保存默认框至少 85% 时，正式 OCR 必须继续使用默认框；只有候选未充分覆盖默认框且累计选中至少 6 个稳定文字框时，才在当前运行使用候选带，并把实际区域统计写入该 OCR 轨成本信息。不得写数据库区域、不改校准页或既有轨。 |
| SUB-LOCAL-OCR-016 | 画面变化不是时间码 | 低成本画面变化只可用于缩小后续检查区间，不能直接成为 cue 起止。Paddle 已选字幕行的代表帧作为视觉参考，首尾局部以 25fps 连续字形证据确定；起点窗口必须覆盖粗采样边界之前完整的 `0.2s`，至少连续两帧才可将该帧认作字幕出现或保持。不得使用 ASR、导入时间码、文字词义或任何外部信号。 |
| SUB-LOCAL-OCR-017 | 真实性与性能 | 第 43 集首条 `我把他当成复仇的刀` 必须从无字幕的 `1.000s` 收敛至实际首个可见字幕帧 `1.080s`，且不写入衣服英文；第 85 集必须使用临时剧集候选带并生成 cue。每集超出 420 秒必须明确失败且不创建 OCR 轨。 |

**非目标：** 本期不增加逐集校准 UI、自动保存剧集覆盖、时间轴编辑、云 OCR、ASR/导入联动、字幕页布局或数据库 schema；这些能力须在本地本机验收稳定后另立需求。

### 10.39 本地 OCR 可移植运行时与发布收口（新增，2026-08-08）

本地 OCR 是桌面产品内置能力。Windows 候选包必须在不依赖开发机 Python、用户目录、工作目录、环境变量或已安装 Paddle 环境的前提下启动本地 OCR runner；运行时依赖可随包携带，但不得把开发虚拟环境配置、缓存、测试工具、数据库、用户素材路径或供应商密钥作为发布物。

| 编号 | 规则 | 验收边界 |

| SUB-LOCAL-OCR-018 | 自包含运行时 | 打包产物只能从应用 `resources` 内的相对位置解析 OCR runner 与 Python 运行时；`pyvenv.cfg`、启动脚本和进程环境不得包含 `C:\\Users\\ZIO`、`D:\\个人工作` 或其它开发机绝对路径。不得依赖用户另行安装 Python、PaddleOCR、PaddlePaddle 或设置环境变量。 |
| SUB-LOCAL-OCR-019 | 发布物数据边界 | 候选包不得包含 `.sqlite/.db`、任何 `.env` 或 `.env.*` 文件、用户配置、API Key、SecretId/SecretKey 的值、媒体文件、OCR 临时文件、Python/pip 缓存、测试文件或测试证书。名称中出现 `secret` 的第三方源码不等于凭据，审计必须区分字段名与实际值。 |
| SUB-LOCAL-OCR-020 | 包级验收 | 对新建、独立且不可覆盖的 Windows 目录包执行：OCR runner 自检、29 项 runner 单元测试、TypeScript 类型检查、完整项目测试、应用启动烟测及发布目录隐私扫描。任何一项失败均不得标记为发布候选。 |

**非目标：** 本期不改变 OCR 检测、识字、时间码、模型、校准区域、三列字幕展示、识别设置、数据库结构或云端 OCR 行为；只替换本地 OCR 的可携带运行时与发布验证链路。

### 10.32 视频硬字幕提取：云端识字阶段（新增，2026-08-06）

本需求的完整能力名为“视频硬字幕提取”：从连续视频画面中发现硬字幕出现、变化与消失，生成独立的时间段，再识别段内文字并输出 OCR 字幕轨。OCR 只是其中的“候选画面识字”阶段，不等同于完整的视频字幕提取能力。用户接受候选图片上传、调用费用和异步等待，因此新增云端识字评估路径；但云端首期不承担视频字幕时间轴检测：本地必须先从视频画面生成候选帧/时间段，不能上传整段视频，也不能用 ASR 或导入字幕决定 OCR 抽帧点、时间边界或文本。

首期只评估腾讯云文字识别的通用印刷体接口 `GeneralBasicOCR`（官方文档：`https://cloud.tencent.com/document/api/866/33526`），使用独立的 OCR 能力配置和 `SecretId + SecretKey`。不得静默复用 ASR 默认方案、改写 ASR 凭据或因 OCR 测试成功切换其它能力默认方案。腾讯云官方接口是图片 OCR；它不是本产品已经验证的“上传视频直接生成字幕”服务。

**区域优先的字幕判定：** 每部剧先独立建立并经操作者确认一个字幕区域；同一剧的后续字幕识别只在该区域内工作。区域内出现的对白、剧情提示和逐字/逐词/逐短语展示的文字都按 OCR 字幕处理，保留原始画面时间段；例如 `PUA / 凌辱 / 家暴` 必须保留。逐字字幕的完整表达只有在人工标注验收集证明规则可靠后才允许重建，当前不得臆测拼句。区域外的人名、身份条和其它剧情视觉标识不参与本期 OCR；它们未来可以独立作为剧情辅助证据采集。`未完待续` 可不保留，但这是一项明确的窄排除，不得借此发展基于词义的“标题/场景文字过滤”。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-CLOUD-OCR-001 | 数据边界 | 用户确认后才开始；只上传本地画面候选图片的 Base64/HTTPS 请求，不上传源视频、ASR、导入 SRT、剧本、数据库或其它业务文件。上传前显示候选图片数量、预计请求量、供应商和数据离开本机提示；用户取消不得发请求。 |
| SUB-CLOUD-OCR-002 | 独立时间轴 | 每个候选图片必须带有本地画面检测产生的原始 `startSeconds`/`endSeconds`；云端只返回文本和识别置信度。不得用云端响应时间、ASR 时间或导入字幕时间修改 OCR 时间段。没有本地候选时间段时，不创建 OCR cue。 |
| SUB-CLOUD-OCR-003 | 能力与凭据 | OCR 配置独立属于 OCR 能力，字段为地址、SecretId、SecretKey、接口/模型预设和超时；密钥只在主进程读取并通过既有安全存储管理，Renderer 不回显。测试入口只验证账号、地址和密钥，不上传候选图片、不创建识别批次、不修改默认方案。 |
| SUB-CLOUD-OCR-004 | 异步状态 | 识别批次持久化逐帧状态：待上传、上传中、识别中、成功、失败、已中断。页面必须区分已发送数量、成功数量、失败数量、首个失败帧和原因；无暂停动作时不得显示“暂停中”。应用关闭/重启后不得把未完成批次伪称成功，继续必须由用户确认。 |
| SUB-CLOUD-OCR-005 | 结果写入 | 只有云端返回可解析文本且对应本地候选时间段有效时，才写入独立 `source_kind='ocr'` cue；成功、失败和部分完成都不得覆盖 ASR、导入字幕或已有 OCR 轨。云端失败、限流、超时、鉴权失败和无文本都必须保留原始本地候选及可理解分类。 |
| SUB-CLOUD-OCR-006 | 成本与限额 | 批量开始前按候选帧数展示请求量和风险提示；本期不伪造精确费用，不自动无限重试，不超出用户确认的候选帧上限。达到上限时暂停提交并等待用户决定减量或终止。 |
| SUB-CLOUD-OCR-007 | 生产门槛 | 云端识字效果变好不等于 OCR 功能通过。只有剧目级字幕区域校准、候选检测、逐字字幕处理、独立时间轴、文本质量、失败恢复、上传边界和实际成本全部通过同一验收集，才允许进入产品接入；否则保留为隔离评估能力。 |

**首期非目标：** 不上传完整视频、不使用云端视频理解或云端 ASR、不让 ASR 为视频硬字幕提取定锚、不改字幕详情 UI、不改三列对照、不增加第二套任务中心、不自动续费或自动重试、不因云端 OCR 可用而删除本地/外置 OCR 路径。

### 10.27 批量字幕识别的持久状态与中断续跑（新增，2026-08-05）

批量字幕识别不得再依赖字幕页 iframe 或 Renderer 内存中的循环状态。一次“一键生成字幕”必须形成仅归属当前剧目的本地识别批次，并逐集记录执行状态，使操作者能区分运行、已中断、单集失败、部分完成与全部完成。此需求只修复字幕资产页的真实状态与续跑，不将字幕识别接入全局任务中心，也不新增暂停/取消控制、后台并发或云端重试。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-RUN-001 | 批次与逐集检查点 | 点击既有“一键生成字幕”后，在开始第一集前持久化本次剧目、识别方式、目标集集合、总数及逐集 `待执行 / 识别中 / 成功 / 失败 / 已中断` 状态；每一集结束立即更新成功或失败原因。原始 ASR/OCR 轨、导入字幕、设置和视频文件均不因记录批次而改变。 |
| SUB-RUN-002 | 状态真实性 | 字幕列表沿用原型已有状态格与工具栏说明位，显示真实“识别中、等待识别、执行失败、已中断、部分完成或已完成”；不得用“已识别 46 集”代替批次状态。对于中断或失败，必须显示首个未完成/失败的集号及可理解原因；没有“暂停”动作时不得显示“暂停中”。单集检查点更新不得被标记为批次终态并触发全量重读；只有 `finish` 写入最终状态后可重读，迟到的运行中快照不得覆盖页面最终状态。 |
| SUB-RUN-003 | 启动恢复 | 应用启动时发现遗留 `识别中` 批次，必须原子标记为“已中断（工具已关闭或重启）”，将正在执行集退回可续跑状态并保留已完成/失败集的真实记录。不得宣称后台仍在继续，也不得把中断写成成功、失败或暂停。 |
| SUB-RUN-004 | 受控续跑 | 操作者再次点击原有“一键生成字幕”时，若当前剧目存在未完成批次，必须先明确提示将从首个未完成集继续，并沿用该批次已保存的目标集与识别设置快照；确认后只处理未完成集，不重复生成已成功集。取消确认不改变批次。真实单集失败保留失败原因并继续后续可执行集，最终如实显示“部分完成”。 |
| SUB-RUN-005 | 范围边界 | 本期不新增全局任务、任务中心条目、通知中心、暂停/取消/重试失败集按钮、跨剧并发、后台驻留、自动恢复、自动重试或新页面/弹层。所有状态仅在当前剧目的字幕资产页读取和展示；继续执行仍必须由用户再次点击并确认，可能产生费用的 ASR 提示继续生效。 |

**验收场景：**

- Given 85 集批次已成功处理第 1–46 集，When 工具在第 47 集前被关闭或重启，Then 返回字幕资产页可见“已中断”、`46 / 85`、第 47 集为首个未完成集及“工具已关闭或重启”；不得显示“暂停中”或“识别中”。
- Given 存在上述已中断批次，When 用户再次点击“一键生成字幕”并确认继续，Then 第 1–46 集不再被调用，第 47 集开始执行，批次进度持续更新。
- Given 第 47 集执行错误但第 48 集可执行，When 批次结束，Then 第 47 集显示“执行失败”及原因，第 48 集仍可成功，批次总状态为“部分完成”。

**非目标：** 本期不重做字幕页视觉结构；三源时间窗、导入/删除、查看画面/状态、识别设置字段、供应商配置、全局任务中心和其它工作区均不改动。

### 10.28 AI 爆点前置二创的连续剧集范围输入（新增，2026-08-05）
“AI 爆点前置二创”任务配置中的剧集范围是连续分析区间，不得再以 `第 1–85 集`、`第 2–85 集` 等组合穷举塞入下拉选择器。页面只提供“全部”和“自定义范围”两种互斥方式；两者最终继续使用既有 `episodeStart`、`episodeEnd` 创建 AI 二创任务，不修改任务服务、分析策略、时长、草稿数、剪辑视角、能力配置或其它工作区。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| REMIX-RANGE-001 | 范围模式 | 默认选中“全部 N 集”，其中 N 是当前剧目有集号剧集的首尾范围；该模式直接使用首集和末集作为既有任务的起止集。切换到“自定义范围”后，才显示起始集与结束集两个数字输入。不得显示或生成任意剧集组合下拉选项。 |
| REMIX-RANGE-002 | 连续输入 | 两个输入均为步长 1 的整数，边界限制在当前剧目的最小、最大集号内。编辑起始集超过当前结束集时，结束集同步提升到该值；编辑结束集小于当前起始集时，起始集同步降低到该值，页面始终保持 `start <= end`。切回“全部”立即恢复首尾范围。 |
| REMIX-RANGE-003 | 规模可见 | 范围控件在原位明确显示“第 X–Y 集 · 共 N 集”。该数量按连续数字区间计算，仅说明本次请求规模，不伪称剧集已经可分析；既有任务创建仍负责校验范围内剧集连续、可读取。 |
| REMIX-RANGE-004 | 范围边界 | 本期不增加离散多选、非连续集组、保存的范围预设、批量任务、预检弹层或自动调整缺集；也不改变现有任务创建失败提示。 |

**验收场景：**

- Given 当前剧目为第 1–85 集，When 打开二创工作区，Then 默认显示“全部 85 集”和“第 1–85 集 · 共 85 集”，页面不存在包含 1–85 组合的剧集范围下拉框。
- Given 用户切换到自定义范围并把起始集改为 12、结束集改为 24，When 点击开始分析，Then 既有任务创建接口收到 `episodeStart=12` 与 `episodeEnd=24`，页面显示“第 12–24 集 · 共 13 集”。
- Given 当前为第 12–24 集，When 用户将起始集改为 30，Then 页面成为第 30–30 集；When 用户将结束集改为 8，Then 页面成为第 8–8 集，按钮不会因表单自身制造的反向区间而失效。

**非目标：** 不改变 AI 二创结果、证据、任务生命周期、供应商调用、费用、字幕、剧集库或其它素材生产入口；范围内存在缺集或不可读素材时，继续由既有任务服务如实阻止创建。

### 10.34 字幕列表显式选集识别（新增，2026-08-06）

字幕识别的“当前剧集”不得再只依赖操作者最近打开过的详情这一隐式状态。字幕资产列表必须允许操作者直接勾选一个或多个可读剧集；有选中项时，列表主操作明确显示本次选中数量，并只对这些剧集创建识别批次，以便单集验证和小范围复核。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-SELECT-001 | 显式多选 | 每个可读剧集行提供可访问的选择框；缺媒体剧集不可选。列表表头可一次选择或取消当前可读剧集。选择仅保留在当前字幕页会话，不写入识别设置、数据库或原片。 |
| SUB-SELECT-002 | 执行优先级 | 存在选中剧集时，“一键生成字幕”必须明确显示“识别已选 N 集”，且目标集合只取已选且可读的剧集，优先于设置中的全部/当前/仅缺失范围。无选中项时，原有范围行为保持不变。已中断批次继续沿用其已保存目标集，不被新的列表选择覆盖。 |
| SUB-SELECT-003 | 范围与安全 | 选中只改变本次识别批次的 episode ID 集合；不更改识别模式、语言、OCR 区域、供应商、导入字幕、已有 ASR/OCR 轨或右侧证据展示。ASR 费用确认、OCR 区域与本机运行前置条件继续逐项生效。 |

**验收场景：**

- Given 列表有第 1、2 集可读且第 3 集缺媒体，When 操作者勾选第 2 集并点击“识别已选 1 集”，Then 新批次仅包含第 2 集；设置即使为“全部”也不加入第 1 集，第 3 集不可勾选。
- Given 没有勾选任何剧集，When 操作者点击“一键生成字幕”，Then 继续按已保存的全部/当前/仅缺失范围处理。
- Given 存在已中断的识别批次，When 操作者改变当前列表勾选后点击继续，Then 继续只处理旧批次未完成的目标集。

**非目标：** 不新增保存的选集预设、跨剧选择、筛选器、全局任务、暂停/取消、并发执行或字幕页之外的入口；不改静态详情、导入/删除、三源对照、校准、供应商或原片。

### 10.35 OCR 字幕区域作用域与自动默认（新增，2026-08-10）

每集字幕位置可能不同，人工校准应是例外覆盖而不是识别前置。识别设置为“自动检测字幕区域”时，每集必须先由本地 OCR runner 做只读全画面预检，在本次执行中独立选择字幕带；该临时区域不得写入区域配置，也不得覆盖人工设置。剧目级区域仅作为可选批量基线，当前集 `episode_override` 优先级最高。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-REGION-001 | 自动默认 | 自动区域模式无需先完成整剧人工校准；有足够稳定文字框时使用本集机器区域，找不到可靠字幕带必须明确失败，不回退为伪造区域。 |
| SUB-REGION-002 | 单集覆盖 | 从当前剧集详情进入校准并确认，保存为该集 `episode_override`；执行该集优先使用覆盖。清除覆盖后恢复机器选择；不得删除 OCR 轨、导入字幕、ASR 或历史记录。 |
| SUB-REGION-003 | 剧目基线 | 从列表工具栏进入校准并确认，保存为 `drama_default`，仅作为机器预检未充分证明位移时的批量基线；不得覆盖已有单集覆盖。 |
| SUB-REGION-004 | 副作用门禁 | 区域候选只用于当前 OCR 运行；不得因为全画面文字检测把标题、水印、角色牌写入字幕轨。已有双行顺序抖动、重叠 cue 等剩余缺口必须在结果与验收记录中如实保留。 |

**非目标：** 不改字幕页既定原型壳、列表与滚动边界，不新增云 OCR，不把 OCR 时间码改由 ASR 或导入字幕提供，不将逐集临时区域自动保存为人工配置。

### 10.40 字幕三链路收口：ASR 句级时间轴与安全验收（新增，2026-08-10）

云端 ASR 的 120 秒音频切段只是上传与任务控制边界，不是字幕 cue 边界。腾讯云 `CreateRecTask` 官方文档说明：`ResTextFormat=1` 返回词粒度时间但不按字幕句分段；`ResTextFormat=3` 才按标点分段并标注为适用字幕场景，`SentenceMaxLength` 可在 6–40 范围内限制单标点最多字数。主产品必须使用官方真实返回的 `FinalSentence`、`StartMs`、`EndMs` 生成 ASR cue，不得按本地分块、标点或均匀时长自行切出时间码。官方参考：`https://cloud.tencent.com/document/api/1093/37823`。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| SUB-ASR-001 | 官方字幕返回格式 | 请求使用 `ResTextFormat=3`，并记录实际 `SentenceMaxLength`、引擎、分块配置和应用版本；仅接受带有效 `StartMs < EndMs` 的云端结果。 |
| SUB-ASR-002 | 时间轴真实性 | cue 起止只能来自腾讯云返回字段并加上本地音频片段的真实偏移；禁止按标点二次切分、用 120 秒边界造 cue 或把 ASR 时间冒充 OCR 时间。 |
| SUB-ASR-003 | 质量门禁 | 对真实样本统计每集 cue 数、平均/最大 cue 时长、时间覆盖和与导入/OCR 的只读差异。粗粒度、无结果、异常密度或覆盖不足的轨道必须显示时间质量不足，并禁止静默作为智能切点唯一锚点。 |
| SUB-ASR-004 | 三链路隔离 | ASR、导入、OCR 保持独立轨道；跨源只按真实时间重叠和文本证据展示差异，不按索引强行一一对应，不因一条轨道异常删除或改写其它轨道。 |
| SUB-ASR-005 | 任务与版本可追溯 | 批量任务的逐集状态、失败原因、取消/重试和最新结果跨页面、重启可恢复；旧 runner/旧批次不得被悄悄当作新结果，升级或迁移不得清空密钥、轨道和历史。 |
| SUB-ASR-006 | 自动切点最低密度 | ASR 轨道按视频时长至少提供每 20 秒一个有效 cue；不足时标记为稀疏时间轴并阻断自动切点，不影响导入/OCR 或手动切片。 |

**本期非目标：** 不用标点规则伪造时间码，不把粗 ASR 结果“修饰”为精确字幕，不改静态原型结构、滚动边界、OCR 画面时间轴或剪映独立工具；ASR 质量不足时先阻断切点误用并如实报告，不以扩大范围掩盖数据质量问题。

### 10.36 剧目资产超短时长异常（新增，2026-08-10）

剧目资产需要对明显不符合分集预期的超短媒体提供非阻断性提示。该提示用于发现导入错误、截断文件或其他资产问题，不得把媒体本身、字幕或生产能力一并封掉。

| 编号 | 规则 | 验收边界 |
|---|---|---|
| ASSET-DURATION-001 | 异常判定 | 有效媒体时长大于 `0` 且小于 `10` 秒时，在既有状态单元显示 `时长异常 · X.XX 秒`；`null`、`0`、`10` 秒及以上不提示。 |
| ASSET-DURATION-002 | 人工忽略 | 用户可在该行既有操作区点击“忽略提示”。忽略仅对当前分集持久化，重启后保持，并从该剧目的异常计数中扣除。 |
| ASSET-DURATION-003 | 非阻断 | 时长异常不改变剧集的可读状态，不禁止播放、OCR、云端 ASR、字幕导入、切片或任务创建。 |
| ASSET-DURATION-004 | 重置边界 | 重新关联到不同源文件时清除该集既有忽略状态，以新媒体探测到的时长重新判断；不删除或移动任何原始文件。 |

**非目标：** 不新增页面、筛选器、全局通知、任务、自动修复、批量忽略或媒体文件操作；不修改字幕识别算法、时间码、超时或已存字幕轨。

补充约束：轨道需记录并可诊断 `resultFormat`、`sentenceMaxLength`、有效 cue 数、平均/最大 cue 时长、时间覆盖率和最大间隔。历史轨道缺少格式元数据时只能标记为旧结果/未验证。智能切片仅接受质量合格的导入、OCR 或 ASR 时间轴作为独立的逐段证据，不设导入 > OCR > ASR 的全剧默认优先级；各来源的文本和原始时间必须保留，差异不得自动合并、平移或覆盖。门禁失败时显示真实原因并阻断候选生成，手动创建候选不受影响。
