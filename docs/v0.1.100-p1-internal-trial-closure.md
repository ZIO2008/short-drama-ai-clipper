# 0.1.100 · 未收束提案自动修正与失败引导修复

日期：2026-10-16。用户在 0.1.98 的第 1 集中已通过字幕预检，但任务失败为“1 条候选结束仍处于铺垫、进入或情绪升级中段，未形成可审阅的叙事收束。前往字幕资产”。只读任务记录显示本集有 3 个可分析窗口，请求 1 条候选；模型只返回一次 escalation/escalation，没有触发修正。

## 根因与修复

原模型结果校验接受 setup/entry/escalation，随后证据资格门禁又拒绝，错过已有的一次自动修正；拒绝分支还无条件附加字幕资产引导。后端与前端重进工作区的恢复判断也把泛“文本/语义”错误当作字幕问题。

现将开放节拍提前拒绝，进入已有的一次受控修正，使用当前冻结窗口重选。未收束的起止范围按冻结时间比较，换证据别名或只改节拍标签不能通过。连续不合格时说明叙事原因；真正字幕、时间轴、媒体故障继续保留相应恢复入口。后续证据资格与收束门槛保留，原始字幕、旧冻结候选和成果不被改写。无 UI 结构、CSS、数据库 schema 变更。

最多两次逻辑语义选择；适配器原有响应格式/空内容兼容回退仍可能使极端情况下达到四次 HTTP 请求，此次没有扩大既有上限。测试使用本地 HTTP 模型响应，未替用户调用真实付费模型，也未自动重跑 OCR/ASR。
