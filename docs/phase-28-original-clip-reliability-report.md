# Phase 28 原剧切片可靠性、压力与隐私证据

## 范围

本 Phase 只收口任务/数据可靠性，不修改候选池、导出模态、完成报告布局，也不修改 V49 静态 HTML。页面迁移分支继续延期。

## 已覆盖的可靠性边界

- 生成请求按冻结输入去重；输入或证据变化进入新轮次，持久化队列按单一供应商槽位排队。
- TaskQueue 已验证安全并发上限、暂停/继续、取消、重启检查点、仅恢复未完成项和失败项重试。
- 生成生命周期已验证取消、关闭中断、有限延期、过期终结、迟到回调拒绝写入。
- 发布指针只接受当前合法轮次；迟到、取消、中断、媒体指纹漂移和伪造轮次不能覆盖稳定结果。
- 导出批次已验证候选抢占、取消释放、重启中断、部分成功保留成果、失败可追溯和成果指针保护。
- 备份使用临时文件、完整性检查、原子提升、七份轮换和最近有效副本恢复；备份会清理分集、导入目录、封面、成果、脚本/字幕资产路径，以及任务配置快照中的路径字段。
- 日志和诊断包统一脱敏；问题报告只写最小 manifest，不包含媒体、字幕、脚本、请求体、路径或密钥。

## 压力基线

新增隔离测试 `src/main/services/phase-28-reliability.test.ts`：

- 85 集资产；合计 5,000 条候选。
- 使用内存 SQLite，候选和源媒体路径均为测试夹具，不写用户数据库或真实媒体。
- `listCandidates()` 返回 5,000 条，分集数量保持 85，首尾时间范围正确，源资产记录保持 85 条。
- 另有 500 项导出任务队列夹具，验证 speed 模式峰值并发不超过 2，500 项全部完成。
- 最近一次 JSON reporter 实测：5,000 候选读取断言约 144 ms，压力测试通过。
