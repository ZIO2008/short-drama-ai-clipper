# 产品需求规范：短剧投流素材生成平台

> 治理迭代（v0.1.11）：本文 P0 内容保留为历史需求事实；当前候选范围为 P1 内部试点，P2 解说/TTS/旁白冻结且不可达。版本和项目库的当前验收规则见 `docs/version-governance.md`、`docs/project-library-governance.md`。

## 0. AI 使用说明

- 本文档是本轮 P0「剧目资产批量导入、排序、删除与长列表滚动」的事实来源。
- 必须完成全部 P0 验收后才能交付目录包；不得删除、移动或覆盖用户的原始视频。
- 未明确的同集号不同文件按安全默认值处理：保留已有引用、报告冲突、继续导入其他剧集。

## 1. 产品上下文

### 1.1 产品摘要

这是 Windows 本地短剧素材管理与生产工具。本轮修复让操作者可将同一剧目的完整视频目录增量导入、按集号正确管理并在长列表中安全维护资产。

### 1.2 用户问题

用户每次导入都要重新定位同一目录；已有部分剧集时整批导入被阻断；列表按错误顺序显示且没有删除入口，85 集长列表无法继续浏览。

### 1.3 目标用户

| 用户类型 | 描述 | 核心需求 |
|---|---|---|
| 短剧投流素材操作者 | 在本地管理几十集到上百集原片 | 快速补齐剧集、确认顺序、修正错误引用且不伤害原片 |

### 1.4 成功标准

| 判断标准 | 目标 / 信号 |
|---|---|
| 批量补齐 | 已有部分剧集后再次选择完整目录，缺失剧集继续导入且已有项不阻断 |
| 正确顺序 | 1、2、3…10、11…顺序在资产页、数据库读取和生产选择中一致 |
| 长列表可用 | 85 集在 100%/125%/150% DPI 下可滚动至最后一行 |

## 2. 范围

| 编号 | 内容 | 原因 |

## 4. 用户流程

### FLOW-001: 增量导入完整目录

**关联任务：** TASK-001
**入口：** 剧目资产页“导入视频文件夹”或编辑剧目“选择视频文件夹”。

**主路径：**
1. 系统以当前剧目最近成功导入目录作为系统选择器初始目录。
2. 用户选择一个视频文件夹；系统递归读取 mp4、mov、mkv、avi、webm。
3. 系统按集号自然排序并将候选与当前剧目比对。
4. 相同已有引用计入“跳过”；不存在的剧集导入；同集号不同文件计入“冲突”且保留已有引用。
5. 系统显示“导入 / 跳过 / 冲突”数量和可识别的冲突项，并刷新资产、健康概览和生产选择。

**边界情况：**
- 取消选择不改变最近目录或剧目。
- 文件夹没有支持视频时显示错误，不更新最近目录。
- 已有剧集不阻断其他缺失剧集导入。

### FLOW-002: 删除错误剧集引用

**关联任务：** TASK-002
**入口：** 剧目资产表每一行的“删除剧集”。

**主路径：**
1. 用户点击删除，确认框明确说明“只删除本软件引用，不删除原始视频文件”。
2. 用户确认后系统删除该剧集应用记录及关联的本地数据。
3. 系统重新读取资产、健康概览和生产资格，列表保持自然排序。

## 5. 功能需求

### REQ-001: 最近导入目录记忆

**优先级：** P0
**关联任务：** TASK-001

**规则：**
- MUST 按剧目保存最近一次成功导入的目录；选择单文件时保存其父目录，选择文件夹时保存该文件夹。
- MUST 在应用重启后仍可恢复，并仅在至少有一个有效导入结果时更新。
- MUST 对首次导入保留系统默认行为。
- MUST 保持文件选择与文件夹选择为两个独立 Windows 对话框。

**验收标准：**
- [x] AC-001: Given 某剧目已成功从目录 A 导入, when 再次选择文件或文件夹, then 系统对话框初始位置为 A。
- [x] AC-002: Given 应用重启, when 打开同一剧目的选择器, then 仍以 A 为初始位置。

### REQ-002: 自然排序与增量合并

**优先级：** P0
**关联任务：** TASK-001、TASK-002

**规则：**
- MUST 在写入、读取、资产页和生产输入中按数值集号升序排序；无集号项置于末尾并稳定排序。
- MUST 将同一真实路径或同集号同文件名的已有项作为跳过，不得使整批失败。
- MUST 将同集号但不同文件作为冲突，默认保留已有项并继续导入无冲突的其他项。
- MUST 返回并展示本次导入的 imported、skipped、conflicts 结果。

**验收标准：**
- [x] AC-003: Given 已有第 1 至 23 集, when 导入含 1 至 30 集的目录, then 第 24 至 30 集被导入，已有项被跳过。
- [x] AC-004: Given 文件名包含 1、2、10、11, when 读取或生产选择, then 顺序为 1、2、10、11。
- [x] AC-005: Given 同集号不同文件, when 导入, then 原引用不变、该项显示为冲突且其他无冲突项继续导入。

### REQ-003: 删除剧集引用

**优先级：** P0
**关联任务：** TASK-002

**规则：**
- MUST 在资产表每行提供删除入口及确认对话框。
- MUST 删除数据库中的剧集引用和应用拥有的关联记录，不得删除或移动 source_path 指向的文件。
- MUST 在成功或失败后给出明确反馈并刷新资产信息。

**验收标准：**
- [x] AC-006: Given 已导入剧集, when 确认删除, then 列表和计数减少且原文件仍存在。

### REQ-004: 长列表浏览

**优先级：** P0
**关联任务：** TASK-003

**规则：**
- MUST 让剧目资产页和表格所在主内容区拥有可达的垂直滚动路径。
- MUST 支持鼠标滚轮、滚动条、PageDown、End 到达最后一集。
- MUST 在 100%、125%、150% DPI 下不因固定高度或 overflow 裁切资产行。

**验收标准：**
- [x] AC-007: Given 85 集剧目, when 使用 End 或滚动条, then 最后一集可见且操作列可用。

## 6. 数据模型

| 实体 | 描述 | 关键字段 |
|---|---|---|
| dramas | 剧目 | id、name、updated_at |
| drama_import_preferences | 按剧目保存导入偏好 | drama_id、last_import_directory、updated_at |
| episodes | 剧集引用 | id、drama_id、episode_no、sort_order、source_path、status |

**数据规则：**
- source_path 仅保存引用；删除剧集永不删除该路径的文件。
- last_import_directory 仅保存本地目录文本，不保存视频内容。

## 10. P1 供应商选择与配置引导（v0.1.17）

### 10.1 问题与目标

现有“能力供应商”入口要求用户先知道供应商名、地址、模型和计费方式，实质是在把产品的选型工作丢回给用户。P1 必须把它改为可筛选的本地供应商目录：用户先按自己要做的能力、费用偏好、质量取向和接入难度选择，再只补该方案确实必要的配置。

本轮只覆盖已被产品使用或已向用户展示的三项能力：`asr`（字幕识别）、`text-analysis`（剧情语义分析）、`multimodal-review`（关键帧/候选片段复核）。P2 解说/TTS/旁白继续冻结，目录、路由、preload 和 IPC 均不得让它变成可用能力。

### 10.2 供应商目录规则

| 编号 | 规则 |
|---|---|
| SUP-001 | MUST 将供应商资料定义在可独立维护的目录数据中，不得散落在 React 组件中。资料至少含：支持能力、区域、费用类型、质量定位、适用/不适用场景、接入难度、预填 endpoint/model、是否需要密钥、官方文档与价格页、核验日期。 |
| SUP-002 | MUST 允许按能力、费用类型（本机运行/免费额度/按量付费/试用待确认）、质量定位和接入难度筛选；无匹配结果时解释如何放宽条件或使用自定义接入。 |
| SUP-003 | MUST 明确“免费额度”不等于永久免费，“本机运行”不等于零成本；所有目录项显示对应提醒，不显示未经官方确认的具体免费额度。 |
| SUP-004 | MUST 将选定项预填到现有配置草稿，保留用户尚未保存的自定义字段；选择目录项不保存、不上传、不覆盖现有密钥，只有用户确认保存才更新该能力的本机默认方案。 |
| SUP-005 | MUST 保留“自定义接入”入口，允许用户填写非目录供应商；已保存的旧配置可继续读取、编辑和保存。历史 `text_semantics`、`video_understanding` 配置必须映射为 `text-analysis`、`multimodal-review`，不得丢失密钥引用。 |
| SUP-006 | MUST 让目录选择实际影响能力状态和项目推荐：已保存本机方案或已保存有效密钥的云端方案显示“已配置”；无方案、缺密钥、能力不匹配显示具体处置。当前 P1 仍仅运行受控本地实现，已配置不表示真实云端调用已启用。 |

### 10.3 目录首批范围与事实边界

目录是“应用已提供预填模板的候选”，不是“全球所有供应商”的宣称。每项的价格/额度信息以官方页面为准，并在资料中记录核验日期；官方页面未给出稳定额度时必须标为“待确认”。

| 方案 | 能力 | 费用标签 | 质量定位/适用场景 | 不适用场景 | 官方来源（2026-07-26 核验） |
|---|---|---|---|---|---|
| whisper.cpp（本机） | ASR | 本机运行 | 不上传原片；适合能自建本地服务的操作者 | 不提供托管 API；模型下载与硬件由用户负责 | https://github.com/ggml-org/whisper.cpp （MIT） |
| Ollama（本机） | 文本分析、关键帧复核 | 本机运行 | 本地模型与本地网络环境；适合隐私优先 | 模型能力、显存和模型许可需自行核对 | https://docs.ollama.com/ |
| Google Gemini API | 文本分析、关键帧复核 | 免费额度 + 按量付费 | 想先用官方免费层验证，再按量扩展 | 免费层配额/地域/模型随官方政策变化 | https://ai.google.dev/gemini-api/docs/pricing |
| OpenAI API | ASR、文本分析、关键帧复核 | 按量付费 | 需要统一的云端 API 与模型选择 | 需可接受跨境数据处理和按量计费 | https://developers.openai.com/api/docs/pricing |
| 阿里云百炼 / Model Studio | 文本分析、关键帧复核 | 试用/额度待确认 | 需要评估国内云服务路径 | 本轮不承诺具体免费额度，开通前以官方价格页为准 | https://www.alibabacloud.com/help/en/model-studio/pricing |

### 10.4 用户流程

1. 用户进入“设置 → 能力供应商”，先选择要解决的能力，再按费用、质量和接入难度筛选候选。
2. 用户展开候选，阅读适合什么、不适合什么、费用提醒、数据区域提醒及官方文档。
3. 用户选择“使用此方案”后，系统仅预填供应商、区域、endpoint、模型、超时与价格提示；对需要密钥的云端方案只提示用户填写密钥，对本机方案提示检查本地服务地址。
4. 用户确认保存后，系统保存本机默认方案及可选密钥引用，并刷新能力状态；若尚未满足密钥/本机地址条件，项目页显示具体受控模式提示与“前往设置”入口。
5. 用户也可选择“自定义接入”；系统不把目录推荐当作强制路径。

### 10.5 安全、隐私与验收

- 密钥只经现有 Windows 当前账户级安全存储保存；目录不得携带密钥、示例密钥或跟踪请求。
- 选择目录项、查看官方链接和保存配置均不得触发云端验证、上传剧集或伪称云端调用成功。
- AC-SUP-001：按“字幕识别 + 本机运行”可得到 whisper.cpp；按“文本分析 + 免费额度”可得到 Gemini；无匹配筛选显示可操作空状态。
- AC-SUP-002：选择目录项会预填配置但不覆盖已保存密钥；用户保存后对应 `asr`、`text-analysis` 或 `multimodal-review` 的能力状态正确刷新。
- AC-SUP-003：旧 `text_semantics`、`video_understanding` 配置迁移后仍可读取，原 secret_ref 保留。
- AC-SUP-004：无密钥云端方案显示“缺少密钥”；本机方案显示“需确认本机服务”，当前 P1 项目页始终说明“受控本地实现，云端适配器未启用”。

### 10.6 供应商配置可发现性与外链行为（v0.1.20）

上一版把三种能力的入口都放在“能力供应商”总览并用长弹窗承载目录。能力虽已按数据过滤，但用户无法从入口直观看出这是三套独立配置，也容易在滚动后才发现筛选和候选。此行为不达标。

| 编号 | 规则 |
|---|---|
| SUP-007 | MUST 将 `asr`、`text-analysis`、`multimodal-review` 呈现为三个独立、可直接进入的配置页面/入口；页面标题、能力说明、当前状态和自定义接入只能对应当前能力，不得让用户误解为共享一份供应商方案。 |
| SUP-008 | MUST 在每个能力页首屏先展示“常见方案”及费用含义，再展示可见的费用快捷筛选（本机运行、免费/试用、按量付费）和质量、接入难度筛选；候选仅显示当前能力可用的条目。筛选不能被放到需要先滚动才能发现的区域。 |
| SUP-009 | MUST 保持目录为“已提供预填模板的常见候选”，而非全网穷尽声明。新增候选前必须核验官方能力与价格资料；免费/试用只写官方明确的层级或“待确认”，不得写死易变额度。 |
| SUP-010 | MUST 让目录中的“官方文档”“价格/额度”统一由 Windows 默认浏览器打开。Renderer 不得依赖 `target=_blank`、WebView、新 BrowserWindow 或当前窗口导航；必须经受限 IPC 交给 `shell.openExternal`，且只接受无用户名密码的 http(s) URL。 |

**用户流程：**

1. 用户进入“设置 → 能力供应商”，看见 ASR 字幕识别、文本语义分析、视频理解复核三个明确入口及各自状态。
2. 进入任一能力页，首屏就能看见该能力的常见方案、费用说明和快捷筛选；例如 ASR 的本机方案、文本分析的免费/试用方案、视频理解的按量付费方案。
3. 用户选择候选后只预填当前能力草稿；未保存的手填字段和现有密钥继续按 SUP-004 保护。
4. 点击官方资料，应用保持当前设置页不变，由系统默认浏览器打开外部地址。

**验收标准：**

- AC-SUP-005：三个能力入口均可独立打开；ASR 页不显示仅支持文本/多模态的 Ollama、Gemini、百炼，文本/视频理解页不显示仅 ASR 的 whisper.cpp。

### 10.8 原剧分集切片与共享字幕资产收口（拟实施，2026-07-29）

现有“原剧切片工作区”只有单集候选、监视器、数字入/出点与字幕文件导入；它既不符合剪辑操作，也把可复用字幕能力错误地塞进了切片页。本节取代此前的“已完成”判断：P0 交付一套先生成候选、再审片编辑的原剧切片工作台，以及不依附任何单一剪辑流程的剧目级字幕资产中心。它们只覆盖 P0 原剧素材；不得借共享字幕能力恢复 P2 解说、TTS 或旁白。

**合并交付边界（2026-07-29 追加）：** 本轮不是交付两张可独立打开的“新页面”，更不是替换整个产品。设计与后续实现必须直接合并进完整静态原型 `short-drama-material-studio.html`：保留其应用壳、全局导航、剧目上下文、资产、素材生产、成果库、任务中心及其既有交互；在同一剧目工作区内替换旧的原剧切片区域，并新增可达的“字幕资产”标签。候选池、导出抽屉和候选内字幕优化是该完整原型中的状态，不得作为孤立 HTML 充当开发依据。用户对本轮设计的确认，覆盖上述完整模块闭环，而非只授权开发两张孤岛页面。

| 编号 | 必须交付 | 验收边界 |
|---|---|---|
| CLIP-001 | 生成优先的工作台入口 | 原片已在资产页导入后，进入切片页的第一可见主操作必须是“生成候选切片”。无候选时给出选择剧集、数量/时长/低重合约束和批量预检；生成后才进入审片与编辑。不得把导入或“切片主题”当作此页的起始任务。 |
| CLIP-002 | 双时间线与真实监视器 | 同时显示当前**源分集时间线**和当前**候选片段时间线**：前者是只读原片，标出该集所有候选的来源区间；后者只显示当前候选的输出时长、入/出点与字幕锚点。它们定位同一个候选，明确“第几集 / 源时码 / 候选编号 / 输出时长”。**不得把不同剧集的候选拼成一条“成片切片序列”来暗示自动混剪。**监视器是工作台的视觉主角，按当前源文件元数据维持真实画幅（默认 16:9；竖片等其他画幅等比适配），视频只可 `contain`，不得因填满布局而裁切或拉伸。媒体可读时显示真实首帧/可播放画面；读取中、未选中、缺媒体三态分别显示可辨识的画面占位、固定画幅框、时间码与状态动作，不得留空黑框、抽象色块或无内容播放器。 |
| CLIP-003 | 源分集与候选切片池 | 左栏标题必须为“源分集”，只展示已导入原片及其生产状态；候选切片不得伪装成剧集。候选显示在一个独立的**全部候选池**：同窗可查看所有分集的候选，按分集分组并有固定组标题，支持“全部 / 当前分集 / 待确认 / 已确认 / 已导出 / 异常”筛选、搜索和跳转，不把候选串成跨集时间线。每个候选是独立输出单元，显示缩略帧、候选编号、源时码、时长、重合提示与确认/导出状态。源分集以文字、图标和状态色明确区分未生成、生成中、待确认、已确认候选、导出中/已导出、失败/缺媒体；候选状态单独累计回写。候选池和源分集列表都只允许各自纵向滚动，滚动轨道必须融入深色 token；1280×720 与 1440×900 主画布不得出现横向溢出或与页面冲突的默认滚动条。 |
| CLIP-004 | 直接操控、候选压力与可控重复 | 主路径使用可见标尺、时间轴拖拽和左/右语义的前后微调；不得以垂直数字输入/上下步进器作为主剪辑方式。工具不得虚构“切片主题”或声称能理解剪辑意图；连续多次生成默认提示并尽量降低候选重合度，操作者可明确允许同一原片段重复入选。候选池必须虚拟化或等效窗口化：以 100 集、每集最多 50 候选（5,000 项）、其中 500 项确认待导出为设计/测试基线；筛选、切换分集、滚动与选中候选不因一次性渲染全部卡片而卡顿，任意时刻只渲染可见窗口及少量缓冲项。 |
| CLIP-005 | 确认后的独立导出 | “生成候选切片”只产生可审阅候选，**不是导出**。确认候选后进入候选池的“待导出”状态；操作者从候选池按单个或批量勾选启动“导出已确认切片”。导出抽屉必须先显示数量、总时长、预计体积、输出目录、命名规则、格式/编码预设、原画幅或明确的输出尺寸、字幕策略（不带 / 软字幕 / 烧录）和冲突处理；默认新建不覆盖文件名。运行后显示每项进度、跳过/失败原因、取消、重试与“在成果库中查看”，输出与原片隔离且不改写原片。 |
| INT-001 | 完整静态原型内嵌 | SCREEN-005、SCREEN-011 以及候选池、导出抽屉、候选内字幕优化均必须嵌入完整 `short-drama-material-studio.html`，并从既有素材生产入口、剧目标签、成果库与任务中心可达。交接截图必须同时呈现原型应用壳和升级区域；禁止把独立 HTML 截图、临时展示页或重做的壳当成最终设计源。 |
| SUB-001 | 共享字幕资产中心 | 字幕按剧目/分集独立管理，作为剧目工作区的独立“字幕资产”标签，而非嵌进切片台；资产中心可被当前切片和后续真实剪辑流程复用。切片台只显示当前字幕可用性与“打开字幕资产”，不承载证据明细或冲突队列。不得为冻结的 P2 新增导航、路由或任务入口。 |
| SUB-002 | 字幕互证与剪辑内优化 | 字幕资产中心将同一时间段拆为两个不可混淆的证据层：**音频实录轨**（ASR，忠于声音）和**画面字幕证据轨**（OCR/导入，忠于画面）。ASR 与 OCR 的职责是互相验证，不是二选一“采纳”；资产中心的核心信息是对齐差异、置信度、缺失侧和校验结论（至少：一致、画面与音频不同、仅音频、仅画面、待校验），而不是让用户在资产页维护“剪辑展示字幕”。字幕文字的省略、润色、断句和时序优化发生在操作者正在编辑的**候选片段**中：候选时间线可显示 ASR/OCR 差异锚点，并把该候选的展示字幕变体与来源时间段、差异原因、操作者关联；它绝不覆盖剧目级原始证据，未来真实剪辑可复用同一契约。资产中心支持 SRT/VTT 导入、固定区域本地 OCR、ASR 交叉校对、冲突定位、建立校验结论、校对 SRT/VTT 与审计导出；无 OCR/ASR 时仍可导入、比较、导出。 |
| SUB-003 | 成本、准确率与合法交换 | 本地 OCR/离线 ASR 默认优先；云 API 只在显式启用、显示模型/数据区域/预估费用/限额后可用。固定样本报告 CER、冲突率、耗时和实际或预估成本，缺引擎只能报告未测。输出 UTF-8 SRT/VTT 与导入说明；只采用剪映桌面公开 SRT 导入和 DaVinci 公开 SRT 互操作，不读写剪映草稿 JSON、不模拟登录、不宣称未公开 API。 |

**用户流程：**

1. 操作者从已导入原片进入切片台，先看到所有分集的明确生产状态和“生成候选切片”主操作；选择一个或多个分集后，先看处理量、预计候选数、重合约束和可跳过项，再开始生成。
2. 生成完成后，操作者在“全部候选池”查看各集独立候选，或从“源分集”定位某集；选中候选后，监视器、源分集时间线与候选片段时间线联动。拖拽或左/右微调修剪后，执行唯一的“确认候选”动作；不得把“审阅”和“确认”做成两个重复关卡，也不得把多剧集候选串成自动拼接的成片。
3. “生成候选”与“导出”是两件事：确认后的独立候选进入待导出池；操作者选择一个或多个候选，检查目录、命名、编码/尺寸、字幕策略和预计体积后启动导出。导出任务与成果库可追溯，失败可重试，源片不被修改。
4. 字幕在剧目级字幕资产中心导入、识别、互证、建立校验结论、导出校对文件；剪辑中的展示字幕优化只发生在正在编辑的候选片段中，引用并保留 ASR/OCR 差异证据。未来真实剪辑能力可复用同一资产契约，但 P2 仍不可达。
